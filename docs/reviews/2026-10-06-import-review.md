## B. Неверные данные

| # | Что | Проверено | Оценка |
|---|-----|-----------|--------|
| B1 | **goszakup кладёт в «потолок цены за единицу» (`max_cost`) сумму лота** (`amount`). В карточке «300 шт · до 54 000 ₸» при цене 180 ₸/шт; калькулятор наценки и позиции заявки сравнивают с суммой; `TenderLotService.recalculateTenderTotal` (Σ max_cost × quantity) при сохранении лота пишет в тендер 123 млн вместо 0,84 млн. СК-Фармация кладёт сюда цену за единицу. | Прод: у 118 из 118 тендеров goszakup Σ max_cost = сумме тендера; API: `amount` 54 000 при `count` 300 | M + миграция данных |
| B2 | **Дедлайн — только дата, JVM прода в UTC**: тендер «принимает заявки» до 00:05 UTC следующего дня (≈ 19 ч после закрытия по Уральску); времени окончания оператор не видит. | Прод: `TZ` не задан, `date` в контейнере — UTC | S (пояс) / M (время) |

| B4 | Лот СК-Фармации без количества (вёрстка «приказ ЕД») уходит поставщику в письме КП как «1 шт.»; единица измерения не хранится. | Код фронта (`?? 1`) и `PriceRequestSendService` | S / M |

1. **Автозапуск в рабочие часы + Telegram «новые профильные тендеры»** (тема в группе «Заявки»: больница, лоты, срок со временем, ссылка). 2. **Журнал прогонов в БД** — «Обновлено» переживает деплой, видно, что и почему пропущено. ≈ M.
3. **Профильные лоты внутри тендера** (пер-лотовый признак): в «приказ ЕД» лекарства и изделия вперемешку. ≈ M.
4. **Охват**: мониторятся только 29 больниц ЗКО.

## Что хорошо и трогать не надо

Сеть вне транзакций, запись тендера — своей транзакцией в отдельном бине, ошибки изолированы по больнице и
объявлению; рынок в фоновом потоке (§6); `LotMergeIndex` (сначала коды, «0 лотов — сбой, а не удаление»);
разбор лотов СК-Фармации по заголовкам (5 вёрсток на реальных фикстурах); релевантность goszakup — по лотам,
а не по имени; токен goszakup — только в заголовке.

## Пакет 1 «Не терять тендеры» — состав и приёмка

Цель: всё профильное, что есть на площадках, попадает в АИС целиком, а то, что не попало, видно в итоге прогона.

| Задача | Что сделать | Чем доказать |
|--------|-------------|--------------|
| A1 фильтр СК-Фармации ✔ | Общий словарь медизделий с goszakup (там уже есть `анализатор`, `гастроскоп`, `реагент`, `тест-систем`, `пробирк`, `электрод`) + недостающее (`тест-полоск`, `экспресс-тест`, `бронхоскоп`, `микроскоп`, `центрифуг`, `маммограф`, `контейнер`…). Вето (`сыворотк`, `инфузи`, `инъекц`, `капсул`, `аэрозол`) — только когда нет сильного термина изделия. «Медицинской техники / медицинских изделий» в имени объявления — достаточный признак. `\b`-регекспы — с `(?U)` (на JDK 19+ без него не работают с кириллицей). | Golden-набор ~60 реальных наименований лотов из фикстур (`lots-ed-order*.html`, `lots*.html`) и прода: до правки краснеет (сейчас узнано 11 из 32 на 522204), после — зелёный; отдельные строки — лекарства/услуги, которые должны остаться отсеянными. |
| A2 фильтр goszakup ✔ | 7 двухсловных стемов → оба стема независимо (или `операционн\S*\s+стол`); решить, побеждает ли NEGATIVE сильный POSITIVE («Кушетка для осмотра», «…с монтажом»); INFO-лог лотов, где сработали оба. | Golden-тест с `description_ru`, не только с названиями; все 7 строк из таблицы A2 — `true`. |
| A3 лоты СК-Фармации ✔ | Снять упор `max-lot-pages` (или поднять до разумного потолка с ошибкой при упоре); сверять число лотов с `SkAnnounce.lotsCount`; неполный список → слияние без удаления + предупреждение «на площадке N, получено M»; 0 лотов при `lotsCount > 0` → ошибка, не «создано». | Тест на упор и на «страница 2 без таблицы»; живьём — 521264-1 (на портале 2485) получает все лоты; на проде после деплоя тендеры «ровно 400» дотягиваются переимпортом. |
| A4 лоты goszakup ✔ | `?limit=` по максимуму API + переход по `next_page`; сверка с `total`; неполный ответ → ошибка, лоты не трогать. | Тест HTTP-клиента на двух страницах (фикстура `{total, limit, next_page, items}`); живьём — `total` = числу записанных лотов. |
| A5 повторы ✔ | Повтор сетевых сбоев (1–2 раза с паузой) для ленты больницы, `subject`, `lots` (есть `GoszakupRetry` для ТЗ) и страниц СК-Фармации; 5xx и обрыв — повторять, 4xx — нет. `fetchSubject` — после фильтра и с кэшем по БИН на прогон (D2), его сбой не роняет тендер. | Тест: первый вызов падает, второй успешен → тендер записан, ошибок 0; живьём — прогон ЗКО без «header parser received no bytes» в итоге. |
| B3 количество и сумма ✔ | Дробное/нулевое количество и сумма ≤ 0 → null (+ пометка в спеке лота), а не CHECK-ошибка; `count` goszakup — BigDecimal. | Тесты на `0.5`, `0`, `2.5`, `amount = 0` для обеих площадок. |
| C1 таймауты ✔ | HTTP-клиенты goszakup и СК-Фармации — через `GatewayHttp` (дедлайн на весь обмен, тело включительно) + `LimitedBytes` (HTML ≤ 5 МБ, PDF ≤ 30 МБ) + `followRedirects(NORMAL)`. | Тест со стабом «заголовки пришли, тело встало» — прогон заканчивается ошибкой с причиной, кнопка разблокируется (как у WhatsApp/westmed). |
