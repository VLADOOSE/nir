# Полировка страницы «Все тендеры» + тёмная тема

**Дата:** 2026-07-19
**Статус:** дизайн утверждён, ждёт плана реализации
**Рынок/охват:** фронтенд Angular 21. Тёмная тема — этот заход только на обрамлении (шапка+сайдбар) и странице тендеров.

## 1. Проблема

Страница `/tenders` («Все тендеры») выглядит утилитарно, особенно на мобилке:
- **Фильтры** — сырые нативные `<select>` + `дд.мм.гггг`-даты в flex-wrap ряду (`.filters`): разной высоты/ширины, с системными стрелками, на мобилке сыплются «в разнобой» и съедают полэкрана до первого тендера.
- **Тёмной темы нет вообще** — глобальный `styles.scss` (54 строки) хардкодит светлые цвета, системы CSS-переменных нет.
- Карточки читаемы, но плотноваты.

## 2. Цели / не-цели

**Цели:**
- Фильтры — аккуратные кастомные контролы единой высоты (десктоп: один ряд; мобилка: кнопка «Фильтры» + шторка снизу + чипы активных).
- Тёмная тема «как Claude» (тёплый тёмный, не чёрный) с тумблером в шапке, сохранением выбора и учётом системной темы при первом заходе.
- Тёмная тема применена и выверена на **обрамлении (шапка + сайдбар + фон приложения)** и **странице тендеров** целиком.
- Лёгкая полировка карточек тендера (сетка деталей, чипы, выравнивание, тач-таргеты).

**Не-цели (YAGNI):**
- Тёмная тема на остальных страницах (делаются отдельно по сигналу оператора; в тёмном режиме их контент пока светлый внутри тёмного каркаса — осознанный промежуточный компромисс).
- Изменение логики фильтрации (`applyTendersFilter` и поля фильтров остаются; меняется только вид + мобильное поведение + чипы активных).
- Переработка модели данных карточки, серверных DTO, импорта.

## 3. Инфраструктура темы

### 3.1 `ThemeService` (`frontend/src/app/services/theme.service.ts`, новый)
По образцу `MarketService`:
- `type Theme = 'light' | 'dark'`.
- Ключ `localStorage['ais.theme']`. При отсутствии — `prefers-color-scheme: dark` → `'dark'`, иначе `'light'`.
- `theme = signal<Theme>(...)`, `current: Theme`, `toggle()`, `set(t)`.
- При инициализации и на каждом изменении ставит атрибут на корне: `document.documentElement.setAttribute('data-theme', t)`. (Светлая — тоже ставит `data-theme="light"` явно, для симметрии.)
- Применяться должен ДО первого рендера, чтобы не мигало: сервис вызывается в конструкторе `AppComponent`/`LayoutComponent` (или провайдер `APP_INITIALIZER`), плюс маленький инлайн-скрипт в `index.html <head>` читает `localStorage['ais.theme']`/`matchMedia` и сразу ставит `data-theme` (анти-FOUC).

### 3.2 Токены (в `frontend/src/styles.scss`)
Семантические переменные на `:root` (светлая) + переопределение на `:root[data-theme="dark"]` (тёмная). Значения — стартовые, финальные хексы выверяются в браузере (§7):

```
:root {
  --app-bg:#f7f7f8; --surface:#ffffff; --surface-2:#f3f4f6;
  --border:#e5e7eb; --text:#111827; --text-muted:#6b7280;
  --accent:#1a56db; --accent-hover:#1e40af; --accent-contrast:#ffffff;
  --danger:#ef4444; --warn:#f59e0b; --success:#10b981;
  --header-bg:#1a56db; --header-text:#ffffff;      /* светлая: синяя шапка как сейчас */
  --shadow:0 2px 8px rgba(0,0,0,.08);
}
:root[data-theme="dark"] {
  --app-bg:#1f1e1d; --surface:#292827; --surface-2:#35332f;
  --border:rgba(255,255,255,.11); --text:#f4f2ee; --text-muted:#a8a29a;
  --accent:#6b93ff; --accent-hover:#8aa9ff; --accent-contrast:#ffffff;
  --danger:#f87171; --warn:#fbbf24; --success:#34d399;
  --header-bg:#242322; --header-text:#f4f2ee;      /* тёмная: тёмная шапка */
  --shadow:0 2px 10px rgba(0,0,0,.45);
}
body { background:var(--app-bg); color:var(--text); }
```

### 3.3 Тумблер темы
Кнопка ☀/☾ (инлайн-SVG path, НЕ динамический lucide — §14 гоча про пустой svg) в шапке `layout.component`, рядом с именем/выходом. Клик → `theme.toggle()`. На мобилке — тоже в шапке (компактно) или в drawer-шапке.

## 4. Охват тёмной темы (что переводится на токены)

**Переводится на `var(--…)` этот заход:**
- `styles.scss` — body, глобальные `.responsive-cards`-карточки, drawer/сайдбар, `.drawer-search`.
- `layout.component` — шапка (`--header-bg/--header-text`), сайдбар (фон `--surface`, текст `--text`, активный пункт `--surface-2`/`--accent`), гамбургер, backdrop.
- `tenders.component` + новый `tenders-filters.component` — все хардкод-хексы → токены.
- Логин-страница НЕ трогаем (отдельная, вне каркаса; остаётся светлой).

**НЕ переводится (остаётся хардкод-светлым, отдельная проработка позже):** dashboard, equipment, facilities, distributors, applies, private-requests, inbound, reports, users, email-template, registry-* и прочие контент-страницы.

## 5. Фильтры — редизайн

### 5.1 Новый компонент `app-tenders-filters` (`frontend/src/app/pages/tenders/tenders-filters.component.ts`)
Изоляция + свой style-бюджет (`tenders.component` большой, §12 CLAUDE.md). Логика фильтрации остаётся в `tenders.component`; компонент фильтров тонкий и «глупый». **Контракт (зафиксирован):**
- Интерфейс `TendersFilters { query:string; status:string; sortMode:string; stage:string; platform:string; facilityId:number|null; deadlineFrom:string; deadlineTo:string; region:string }`.
- **Inputs:** `@Input() filters: TendersFilters`; `@Input() facilities: any[]`; `@Input() regions: string[]`; `@Input() isKz: boolean`; `@Input() noRegionValue: string` (значение «Регион не указан»).
- **Outputs:** `@Output() filtersChange = EventEmitter<TendersFilters>` (эмитит НОВЫЙ объект при любом изменении поля — родитель присваивает и зовёт `applyTendersFilter()`); `@Output() reset = EventEmitter<void>`.
- Родитель хранит единый объект `filters` (мигрирует существующие `filterQuery/filterStatus/…` в него или маппит), передаёт вниз, на `filtersChange` — обновляет и фильтрует.
- Внутри компонент держит `sheetOpen:boolean` (мобильная шторка) и `get activeChips()` — список `{label:string, key:keyof TendersFilters}` для непустых фильтров; клик ✕ эмитит `filtersChange` с очищенным полем.

### 5.2 Десктоп (>900px)
Один ряд `.filters-row` (flex, `gap`, единая высота 38px): поиск (растягивается, `flex:1`), затем кастомные `<select>` одинакового вида (свой шеврон-SVG как `background-image`, `appearance:none`, `--surface`/`--border`/`--text`), даты (стилизованный `input[type=date]`), «Сбросить» в конце. Перенос на 2-й ряд только на узком десктопе — но контролы всё равно выровнены (одинаковая высота, общий стиль).

### 5.3 Мобилка (≤900px)
- Видны только: **поиск** (полная ширина) + строка **`[ ⚙ Фильтры · N ]  [Сбросить]`** (N = `activeCount`, скрыт если 0) + **чипы активных** (каждый `<label> ✕`, клик по ✕ сбрасывает только это поле).
- Тап «Фильтры» → **шторка снизу** (`.filter-sheet`, slide-up + `.filter-backdrop`): заголовок «Фильтры ✕», строки «подпись + контрол» (Статус/Стадия/Площадка(KZ)/Регион(KZ)/Учреждение/Дедлайн от–до), внизу «Применить» (закрывает) + «Сброс». Закрытие по ✕/backdrop/Применить. Паттерн slide-up + backdrop — как у сайдбар-drawer в `styles.scss`.
- Тач-таргеты ≥40px, инпуты `font-size:16px` (анти-зум iOS).

### 5.3.1 Чипы активных фильтров
`activeChips` считаются из значений: для каждого непустого фильтра — `{label, clear()}`. Метки человеко-читаемые (Статус→«Приём заявок», Площадка→«Госзакуп», Регион→сама строка, Дедлайн→«до 22.07»). Клик ✕ на чипе → сброс поля + `applyTendersFilter`.

## 6. Полировка карточек (лёгкая)
- Чипы статуса/площадки — на токенах, единый радиус/паддинг; статусные цвета через `--success/--warn/--danger/--accent` с прозрачным фоном.
- Сетка деталей — выровнять колонки, `--text-muted` для подписей; на мобилке 1 колонка если тесно.
- Цена — выровнять по правому краю, `--text` жирным; валюта из `market.symbol()`.
- Ховер карточки — `--shadow` + `--border`. Левый бордер urgent/overdue — `--warn/--danger`.

## 7. Проверка (браузер + сборка)
- **Playwright, 4 комбинации:** {десктоп 1280, мобилка 390} × {светлая, тёмная}. Скриншоты каждой; глазами выверить палитру (тёплый тёмный, контраст текста ≥ WCAG AA на глаз), фильтры (десктоп ряд ровный; мобилка — поиск+кнопка, шторка открывается, чипы сбрасывают поля), карточки.
- **Анти-FOUC:** перезагрузка в тёмной теме не мигает светлым.
- **Тумблер:** переключает, выбор переживает reload, уважает системную тему при чистом localStorage.
- **Регресс:** логика фильтров работает (каждый фильтр + сброс + чипы), список фильтруется как раньше.
- **Гейт сборки:** `cd frontend && npm run build` — зелёный, без превышения `anyComponentStyle`-бюджета (вынос фильтров в отдельный компонент разгружает `tenders.component`).
- Другие страницы: быстрый визуальный проход в тёмном режиме — не сломаны (светлый контент в тёмном каркасе допустим, но без нечитаемого текста).

## 9. Порядок реализации (для плана)
1. Токены + `ThemeService` + анти-FOUC + тумблер в шапке; перевод каркаса (шапка/сайдбар/body) на токены. Проверка: тумблер темнит каркас.
2. Перевод `tenders.component` на токены (карточки, тулбар, прогресс) — страница целиком в тёмном.
3. `app-tenders-filters`: десктоп-ряд (кастомные контролы) + вынос из `tenders.component`. Проверка десктоп.
4. Мобилка: кнопка «Фильтры» + шторка + чипы активных. Проверка мобилка светлая/тёмная.
5. Полировка карточек.
6. Playwright 4 комбинации + `npm run build` + визуальная выверка палитры.

## 10. Гочи (из CLAUDE.md §14, соблюдать)
- `@media` в инлайн-стилях компонента — только В КОНЦЕ блока `styles` (позднее базовое правило перебивает раннюю @media при равной специфичности).
- Иконки тумблера/гамбургера — инлайн-SVG с захардкоженными path, не динамический lucide (пустой svg).
- Bash cwd персистит: `cd frontend && npm run build` одной командой; git/gradlew из корня.
- Style-бюджет `anyComponentStyle` (angular.json) — следить; вынос фильтров помогает.
