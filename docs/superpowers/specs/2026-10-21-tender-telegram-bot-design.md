# «Наш тендер — с телефона за минуту»: кнопки бота в Telegram, ответ ИИ, письмо заводу с бронью

**Дата:** 2026-10-21. **Рынок:** KZ (тендеры). **Объём:** вариант C без API Claude, кнопки прямо в Telegram,
«Вставить ответ ИИ» и в АИС; ≈ 4–5 дней + 2–3 ч (выбор оператора).
**Связано:** `2026-10-19-product-watch-design.md` (поиск нашей продукции, тема 95), `2026-10-20-product-spec-fit-design.md`
(сверка ТЗ, «📋 Для ИИ»), `2026-10-20-lot-model-in-work-design.md` (модель в работе),
`2026-10-12-private-request-workspace-design.md` §6 (запрос на бланке, «Указать клиента»).

## 1. Зачем

Оператор (2026-10-21): первыми найти тендер, где есть наш товар (Фотек, Аксион…), сразу забронировать проект у завода,
узнать цену и готовиться к тендеру — всё с телефона: «в тг пришёл алерт — можно быстро проверить и отослать запрос».

Сейчас в тему 95 приходят только «★» и «✅ подходит» от 1 млн ₸ (на проде — почти ничего); «📋 Для ИИ» есть только в АИС;
совет ИИ закрепляется руками (раскрыть лот → «📌 Модель…» → набрать модель); письмо запроса цен намеренно не называет ни
тендер, ни больницу — забронировать по нему проект завод не может.

**Успех:** из сообщения в Telegram, не заходя в АИС, оператор отдаёт пачку тендеров своему ИИ и возвращает ответ, а АИС
сама закрепляет наши модели. Затем оператор просматривает письма заводам на бланке со строкой «Конечный заказчик:
<больница>. Просим закрепить проект за West-Med.» и отправляет каждое одним нажатием. Статусы и история — как при работе
в АИС, с пометкой «Telegram».

## 2. Решения оператора (2026-10-21)

1. **Без API Claude пока** — стоит денег, а продаж ещё нет. ИИ — свой (Claude / Gemini по подписке), копированием. Формат
   ответа ИИ и его разбор — такие, что API потом подключается без переделки (вне рамок, §15).
2. **Кнопки работают прямо в Telegram** — в группе только оператор и отец. Бот тот же — @West_Med_bot: сайт и medsite
   только отправляют сообщения, обновления бота никто не читает (проверено по коду обоих).
3. **Тендер не раскрываем.** В письме — строка о больнице-заказчике и просьба закрепить проект (как «Указать клиента» в
   частных заявках); номера тендера и ссылки нет.
4. **Письма — на фирменном бланке во вложении**, как у частных заявок. В боте: «👁 N» → фото страницы бланка с кнопками
   «⬅ Вернуться · ✅ Отправить · ✏️ Открыть в АИС»; после отправки бот удаляет фото и пишет «Письмо <поставщику> отправлено».
5. **Кому:** завод бренда закреплённой модели (карточка «Производитель» с почтой); нет — «Доверенные» поставщики этого бренда
   с почтой. Остальным дилерам бот не пишет — им из АИС, как сейчас.
6. **Сообщение — после каждого поиска:** только новые тендеры с любой нашей отметкой, наши лоты от 1 млн ₸. «★» и «✅»
   входят в это же сообщение — в теме 95 один поток.
7. **Автозакрепление:** только «идти» + наш товар по коду из текста для ИИ; модель, закреплённую вручную, не трогает;
   «не наше» больше не приходит.
8. **Кто нажал:** Telegram ID — в «Пользователях»; кнопки работают только у администраторов; в «Истории» — «· vlad, Telegram».
9. **«✍️ Вставить ответ ИИ» — и в АИС** (над списком тендеров и в карточке тендера): тот же разбор — весь круг с компьютера
   без Telegram и запасной путь, если бот выключен.
10. **Выключено по умолчанию;** пока выключено — всё как сейчас.

## 3. Как работает (на телефоне)

1. Поиск нашей продукции нашёл новые тендеры → в теме 95 сообщение «🔎 Потенциально наших тендеров: 3» (§4) с кнопками
   «📋 Для ИИ · ✍️ Ответ ИИ · Открыть в АИС».
2. «📋 Для ИИ» → бот присылает файл «Для ИИ — 3 тендера, 21.10 10:33.txt» (§5) → «Поделиться» → Claude (или открыть файл,
   «Выбрать всё», скопировать, вставить в Claude).
3. ИИ отвечает разбором, а в конце пишет блок «Для АИС» отдельным блоком кода. Оператор копирует блок его кнопкой
   «Копировать» в Claude / Gemini.
4. «✍️ Ответ ИИ» → бот просит ответить ему блоком (Telegram сам открывает ответ) → оператор вставляет. Можно и просто
   ответить блоком на любое сообщение бота.
5. Бот разбирает (§6): закрепляет наши модели и одним сообщением пишет итог по лотам и список писем с кнопками «👁 1», «👁 2».
6. «👁 1» → фото бланка с подписью (кому, тема, начало письма) и кнопками (§7). «✅ Отправить» → письмо ушло, фото
   удалено, «✅ Письмо ООО «Аксион» отправлено · vlad».
7. Ответ завода — как сейчас: цена встаёт в АИС с 💡, уведомление — в тему «Почта zakup@».

## 4. Сообщение о потенциальных тендерах

**Кого.** То же правило, что у нынешнего «Наш товар» (`ProductWatchNotifier`): тендеры KZ в статусе ACTIVE с отметкой выше
сообщённой, приём ещё идёт (по часам рынка), сумма наших лотов не меньше порога (`ProductNotifyPolicy`, 1 млн ₸); уровни —
по `PRODUCT_WATCH_NOTIFY` (для этого режима — ALL, §11). Новое: лоты с выводом ИИ «не наше» (§6) в сообщение не идут и в
сумму не входят; тендер, у которого все наши лоты «не наше», молча отмечается сообщённым. Зовётся там же, где сейчас:
после поиска по стране и импортов ЗКО / СК-Фармации.

**Сколько.** В одном сообщении — до 15 тендеров (столько берёт текст «Для ИИ») и не длиннее предела Telegram (4096 знаков
видимого текста); не поместилось — следующим сообщением со своими кнопками. Порядок — точнее сверху (★, ✅, ◐, 🏷), внутри —
у кого приём кончается раньше. Звук — если в сообщении есть ★ или ✅, иначе тихо. Сообщёнными отмечаются тендеры,
вошедшие в отправленное сообщение (как сейчас).

**Текст** — разметка HTML Telegram; поля площадки — одной строкой (`TelegramText.oneLine`) и экранированы:

```
🔎 Потенциально наших тендеров: 3
1. ✅ Дефибриллятор — ГКП «Горбольница №7», Алматы
   наши лоты 12,5 млн ₸ · до 02.11 14:59 · подходит наш ДКИ-Н-12 (Аксион) · 21 из 34
2. 🏷 Облучатель бактерицидный, 3 шт. — Поликлиника №2, Уральск
   1,2 млн ₸ · до 25.10 10:00 · наш вид: облучатели · похоже: ОБПЕ-450 (Фотек)
```

- значок — уровень тендера: ★ (ТЗ списано / назван наш товар), ✅ подходит, ◐ похоже (есть ✓), 🏷 наш вид; повышение уже
  сообщённого тендера — «⬆ Уточнение: …»;
- первая строка — наши лоты (до 2, дальше «и ещё N»), заказчик, регион; название лота — ссылка на карточку тендера в АИС
  (`…/tenders?openId=<id>&market=KZ`);
- вторая строка — сумма наших лотов («12,5 млн ₸»), срок приёма, наша отметка (тексты — как в карточке тендера).

**Кнопки:** «📋 Для ИИ» и «✍️ Ответ ИИ» — обратный вызов боту; «Открыть в АИС» — ссылка `…/tenders?ids=<id,…>&market=KZ`
(список ровно с этими тендерами).

Пачка сообщения хранится (`product_digest`, §9): по нажатию бот знает, какие тендеры в неё вошли, в том числе после
перезапуска.

## 5. Текст для ИИ и блок «Для АИС»

Текст — прежний «📋 Для ИИ» (`ProductAiBrief`) с двумя добавками — одинаково в боте и в АИС:

- **коды:** у заголовка лота — «[L5826]» (id лота), у нашего товара-кандидата — «[P123]» (id товара сайта);
- **просьба в конце запроса** закончить ответ блоком «Для АИС» — отдельным блоком кода, по строке на лот:

  ```
  L5826 | идти | P123 | ТЗ совпадает: 14 ступеней, заряд ≤ 4 с
  L5830 | не наше | — | нужен передвижной облучатель
  L5831 | не ясно | — | нет данных о мощности
  ```

  «идти» с кодом товара — только если этот наш товар подходит по ТЗ; не наш товар — «идти» без кода, модель и № РУ — в
  «почему».

Бот присылает текст файлом «Для ИИ — N тендеров, ДД.ММ ЧЧ:ММ.txt» (UTF-8; время — по Уральску) ответом на сообщение пачки:
в сообщение Telegram влезает 4096 знаков, в кнопку «копировать» — 256, а текст по пачке — десятки тысяч.

## 6. Разбор ответа ИИ — общий для бота и АИС

`AiAnswerService.apply(text)` — рынок KZ; кто — вошедший пользователь, у бота — сопоставленный по Telegram ID (§8).

**Строки.** Ищутся во всём тексте — блок кода и лишний текст вокруг не мешают: код лота `L\d+` (в скобках или без),
вердикт, код товара `P\d+` или «—», «почему». Вердикт — без учёта регистра: «идти» / «да» → ИДТИ; «не наше» / «нет» /
«не идти» → НЕ НАШЕ; «не ясно» / «?» → НЕ ЯСНО. Повтор лота — берётся последняя строка. Строка с кодом лота, которую не
разобрать, — в итог «не понял: …».

**Проверки по строке:**
- лот — тендера KZ вида `PUBLIC_TENDER`, иначе «лот L… не найден»;
- код товара — один из наших кандидатов ЭТОГО лота (кандидаты сверки и товар отметки — те, что были в тексте для ИИ), иначе
  «товар P… не из кандидатов лота — не закрепляю»;
- товар снят с сайта — «снят с сайта — не закрепляю».

**Что делает:**
- вывод записывается у лота всегда: вердикт, товар, «почему» (до 500 знаков), кто, когда (§9);
- ИДТИ + наш товар: у лота нет модели или её закрепил ИИ — закрепить этот товар (`LotModelService.pinSiteProduct`, заметка
  «ИИ: <почему>») с пометкой «закреплено ИИ»; модель, закреплённая вручную, не меняется — в итоге «у лота уже <модель>
  (<кто>), ИИ советует <товар> — замените в АИС»; та же модель — «уже в работе»;
- ИДТИ без нашего товара — в итог совет ИИ («почему»); закрепить можно в АИС;
- НЕ НАШЕ — лот больше не идёт в сообщения (§4);
- НЕ ЯСНО — только записывается;
- приём по тендеру закончился — вывод записывается, модель не закрепляется: «приём закрыт».

**Письма** (у бота — черновики `bot_letter`, у АИС — подсказка «КП ›»). По каждому тендеру — по поставщику на лоты, где
модель в работе — наш товар, закреплённый этим ответом или совпавший с советом ИИ. Поставщик (§2 п. 5):
1. карточка «Производитель» с брендом модели (`BrandMatch`) и почтой;
2. нет такой — «Доверенные» с брендом и почтой (все такие);
3. нет и их — в итог «письмо — из АИС: нет завода бренда «…» с почтой».

Поставщику, которому запрос по этому лоту уже уходил, письмо не готовится — в итоге «уже запрошено ДД.ММ».

**Итог** — список по лотам: «✅ <лот> · <заказчик> → <модель> — закреплено», «✕ <лот> — не наше: …», «❔ <лот> — не ясно: …»,
«⚠ …» для отказов и «не понял», затем письма.

## 7. Письма из бота

**Список.** Итог разбора бот присылает одним сообщением ответом на вставленный блок: итог по лотам (§6) и «📨 Письма к
отправке: 1. ООО «Аксион» (завод) — Дефибриллятор, ГКП «Горбольница №7», Алматы · 2. …» с кнопками «👁 1», «👁 2».
(Одним сообщением, а не кнопкой «📨 Письма» и вторым сообщением — на одно нажатие меньше.)

**Письмо** — то же, что отправила бы панель «КП» тендера с этими настройками (`PriceRequestSendService`, без нового пути
письмостроения):
- позиции — «— <модель> (<бренд>), РУ № … — N шт.»;
- «Указать клиента» — да: строка «Конечный заказчик: <больница>. Просим закрепить проект за West-Med.» в письме и в
  документе (`RfqClientLine`); номера тендера и ссылки нет;
- запрос на бланке (Word) — во вложении; печать — если загружена;
- «Ответить до» — за 2 дня до конца приёма; если это раньше завтрашнего дня — завтра, но не позже дня окончания приёма
  (приём кончается сегодня — сегодня); срока нет — через 3 дня.

**«👁 N»** — бот собирает черновик запроса (`PriceRequestSendService.draft` + `RfqDocumentService.preview`) и присылает
ответом на список фото первой страницы бланка. Подпись (до 1024 знаков): «Письмо N из M · <поставщик> (завод)», «Кому:
<адрес>», «Тема: …» и начало текста письма. Бланк на 2 и больше страниц — вместо фото PDF-файл. Кнопки:
- «⬅ Вернуться»;
- «✅ Отправить»;
- «✏️ Открыть в АИС» — ссылка `…/tenders?openId=<тендер>&lot=<лот>&kp=<поставщик>&market=KZ`: карточка тендера на этом лоте
  с панелью «КП», в которой отмечены этот поставщик и «Указать клиента».

**«✅ Отправить»:**
1. черновик переводится в «отправляется» одним условным UPDATE: повторное и одновременное нажатие — «уже отправляется» /
   «уже отправлено»;
2. проверки: модель лотов та же, что в черновике (иначе «модель лота изменилась — откройте письмо заново»); приём идёт;
   поставщику по этим лотам после черновика не уходил запрос из АИС (иначе «уже отправлено из АИС в ЧЧ:ММ» — черновик
   закрывается);
3. отправка — тем же `PriceRequestSendService.send`, что у панели «КП»; у запроса цен — автор (§8);
4. фото удаляется; ответом на список — «✅ Письмо ООО «Аксион» отправлено · vlad»; пункт списка — «✅ … отправлено ЧЧ:ММ»,
   его кнопка убирается.

Почта не приняла письмо (сбой SMTP — «письмо не ушло») — запрос цен записан, как и сейчас; черновик — «не ушло» с причиной,
бот её пишет. Повторное «✅ Отправить» делает «↻ Переслать» этого запроса, а не второй запрос.

**«⬅ Вернуться»** — фото удаляется, письмо не уходит.

## 8. Бот: нажатия, кто нажал, защита, сбои

**Приём.** Свой однопоточный цикл `telegram-bot`: long-poll `getUpdates` (timeout 25 с, дедлайн всего обмена 35 с —
`GatewayHttp`), только `message` и `callback_query`. Снаружи ничего не открывается — калитка и nginx не меняются. При старте
бот узнаёт свой id (`getMe`) и пропускает накопившиеся обновления (`offset` = последнее + 1): нажатия во время перезапуска не
выполняются — иначе письмо могло бы уйти через час после нажатия. Рынок — KZ (`MarketContext` в потоке); работа с БД — в
`@Transactional`-методах отдельных бинов (CLAUDE.md §6).

**Что слушает.**
- Только группу `TELEGRAM_CHAT_ID`; личные сообщения и другие чаты — мимо.
- Обратные вызовы — по своим сообщениям; `callback_data` проверяется: пачка и черновик существуют, а статус черновика
  допускает это действие.
- Сообщения — только ответы на сообщения бота (privacy mode бота их пропускает). Нет блока «Для АИС»: если это ответ на
  просьбу «✍️ Ответ ИИ», на сообщение пачки или на файл — «блок «Для АИС» не найден — скопируйте блок кода из конца ответа
  ИИ»; иначе молча мимо.

**Кто нажал.** `from.id` → учётка АИС с этим Telegram ID и ролью ADMIN.
- Такой учётки нет — всплывающее окно только нажавшему: «Ваш Telegram ID 123456789 — впишите его в «Пользователи» АИС»
  (на сообщение — ответ с тем же текстом).
- Учётка есть, но не администратор — «Нет доступа: нужна роль администратора».
- Действие выполняется от имени учётки: бот ставит в своём потоке вход этого пользователя и пометку «Telegram» на время
  обработки, поэтому прежние пути (закрепление модели, события сделки, запрос цен) сами пишут «vlad, Telegram»
  (`CurrentUser`).

**История.** «Лот «…»: модель в работе — ДКИ-Н-12 (Аксион) — по ответу ИИ · vlad, Telegram»; «Запрос цен: письмом — ООО
«Аксион» · vlad, Telegram». Автор запроса цен теперь пишется и при отправке из АИС — «· vlad». Вывод ИИ у лота — с «кто,
когда».

**Сбои.**
- Telegram 429 — ждать `retry_after` и повторить (предел — 20 сообщений в минуту в группу, общий с сайтом и medsite); сеть —
  повтор через 5 с … 1 мин.
- 401 (токен) — пауза 10 мин, ERROR в лог. 409 (у бота стоит вебхук — кто-то начал читать обновления) — цикл
  останавливается, ERROR «кнопки бота не работают: у бота установлен вебхук»; сообщения о тендерах уходят как раньше.
- Обработка одного нажатия упала — бот отвечает «Не получилось: <своя причина> — повторите или откройте в АИС»; цикл живёт.
- В лог — без текстов писем и ответов ИИ, только id и классы ошибок; токен — нигде (как в `TelegramClient`).

## 9. Данные (V41)

- `user_account.telegram_user_id BIGINT UNIQUE` — Telegram ID учётки.
- `price_request.created_by VARCHAR(100)` — кто отправил («vlad», «vlad, Telegram»); у старых — пусто.
- `tender_lot`: `ai_verdict VARCHAR(10)` (GO / NO / UNSURE), `ai_product_id BIGINT REFERENCES site_product(id) ON DELETE
  SET NULL`, `ai_note VARCHAR(500)`, `ai_by VARCHAR(100)`, `ai_at TIMESTAMPTZ` — последний вывод ИИ;
  `model_by_ai BOOLEAN NOT NULL DEFAULT FALSE` — модель закрепил ИИ (ручная установка и снятие — false).
- `product_digest` — сообщение-пачка: `id`, `created_at`, `message_id` (Telegram), `tender_ids JSONB`.
- `bot_letter` — черновик письма из бота: `id`, `tender_id REFERENCES tender(id) ON DELETE CASCADE`, `distributor_id
  REFERENCES distributor(id) ON DELETE CASCADE`, `items JSONB` (лот, позиция каталога модели, количество), `status` (DRAFT /
  SENDING / SENT / FAILED / ELSEWHERE / CANCELLED), `price_request_id REFERENCES price_request(id) ON DELETE SET NULL`,
  `list_message_id`, `preview_message_id`, `created_at`, `created_by`, `sent_at`, `sent_by`, `error VARCHAR(300)`.

## 10. Экран АИС

1. **Лот** (карточка тендера): строка «🤖 ИИ: идти — ДКИ-Н-12 (Аксион) · <почему> · vlad, Telegram, 21.10» (две строки,
   нажатие — целиком); «🤖 не наше: …», «🤖 не ясно: …».
2. **Панель «КП» лота** (и «КП по выбранным»):
   - у каждого поставщика — «Указать клиента»: по умолчанию отмечено у завода и «Доверенных»; в письме и документе —
     строка о больнице. Запрос отправки и предпросмотра несёт список поставщиков с клиентом (`discloseClientIds`);
   - по бренду модели первым и отмеченным стоит завод с почтой, дилеры бренда — без отметки (как в частных заявках,
     `PrivateRequestSourcingService`); у завода — метка «завод»;
   - `?lot=&kp=` в адресе карточки — раскрыть лот, открыть панель «КП», отметить поставщика.
3. **Список «Тендеры»:**
   - `?ids=` — только эти тендеры и плашка «Пачка из Telegram: N тендеров · Показать все»;
   - рядом с «📋 Для ИИ» — «✍️ Вставить ответ ИИ»: окно с полем, «Разобрать» → итог по лотам (§6) с «КП ›» у писем —
     ссылка в карточку на панель «КП» с этим поставщиком. Та же кнопка — в карточке тендера.
4. **«Пользователи»** — поле «Telegram ID» (цифры, уникально).
5. **«История» тендера** — автор у запросов цен.

«✍️ Вставить ответ ИИ» видит только администратор; оператор видит вывод ИИ у лота.

## 11. Настройки и включение

- `TELEGRAM_BOT_ACTIONS_ENABLED` (умолчание false). Если true, Telegram настроен и включена «наша продукция» — сообщения о
  тендерах в новом виде с кнопками (§4) и цикл приёма нажатий (§8); false — всё как сейчас.
- Раскатка (DEPLOY.md §11): push → `PRODUCT_WATCH_NOTIFY=ALL` и `TELEGRAM_BOT_ACTIONS_ENABLED=true` в `/srv/ais/.env` →
  пересоздать бэкенд → нажать любую кнопку бота: он скажет Telegram ID → вписать ID оператора и отца в «Пользователи».
- Первый поиск после включения пришлёт все открытые потенциальные тендеры, о которых раньше не сообщали (≈ 2–4 сообщения по
  15). Не нужно — до включения пометить их сообщёнными SQL (DEPLOY.md §11).

## 12. Что не меняется

Письма запроса цен остальным поставщикам — без больницы и тендера (анти-лик, CLAUDE.md §9); приём ответов поставщиков,
сверка ТЗ, отметки «наш товар», «📌 Модель…» и сверка модели; темы «Почта zakup@» и «Тендеры» — без кнопок.

## 13. Ограничения

- ИИ — вручную: ответ ждать минуты, качество — за ИИ; ошибку ИИ ловит просмотр письма перед отправкой.
- Текст для ИИ одной кнопкой в Telegram не скопировать — только файлом. Появится ли Claude в «Поделиться» для файла —
  проверить на iPhone оператора (иначе «Выбрать всё» → скопировать).
- Длинный ответ ИИ целиком Telegram режет на несколько сообщений — копировать только блок «Для АИС».
- Письмо в Telegram не правится — только «Отправить» или «Открыть в АИС».
- Бот общий с сайтом и medsite: если они начнут читать обновления бота — кнопки встанут (409 в логе); лечение — свой бот
  АИС.
- Свои сообщения бот может удалить только в первые 48 часов (Telegram): старое фото письма останется, но второго письма
  «Отправить» не пошлёт.
- Модель не нашу (запись реестра) по ответу ИИ бот не закрепляет — только пишет совет; закрепить можно в АИС.
- Нажатия во время перезапуска АИС (деплой) теряются — нажать ещё раз.

## 14. Проверка

- **Тесты** — красный до правки, мутации — по каждой защите:
  - разбор блока: формы строк, вердикты, коды в скобках и без, блок кода и текст вокруг, мусор, повтор лота;
  - `apply`: закрепление, ручная модель не трогается, модель ИИ заменяется, код не из кандидатов, снятый товар, чужой рынок
    и вид, приём закрыт, «не наше» уходит из сообщений;
  - получатели: завод с почтой → доверенный → нет;
  - письмо: строка о больнице, бланк, «Ответить до», печать — если загружена;
  - сообщение: до 15 и предел длины, звук, HTML-экранирование, сумма, «не наше» вне суммы, сообщёнными — только вошедшие;
  - бот: незнакомый — окно с ID, не администратор — нет доступа, чужой чат — мимо, двойное нажатие — одно письмо, «уже
    отправлено из АИС», сбой почты → «↻ Переслать», модель изменилась, накопившиеся при старте — пропуск;
  - `TelegramClient`: multipart фото и файла с кириллицей в имени, разметка кнопок, правка и удаление сообщения, ответ на
    нажатие, `getUpdates`, 409 / 429 / 401, токен не в текстах;
  - «История» с автором; API: `POST /api/tenders/ai-answer` — только ADMIN, Telegram ID уникален (400), отправка с
    «Указать клиента».
- **Заглушка Bot API** (`scripts/telegram-stub.mjs`): очередь `getUpdates`, `/__press` (нажатие), `/__reply` (ответ на
  сообщение), приём `sendPhoto` / `sendDocument` / `editMessageText` / `deleteMessage` / `answerCallbackQuery`, `getMe`.
- **Живая проверка** локально: заглушка + `./gradlew devMail` + браузер (1280 / 390, обе темы, оператор, РФ) — весь путь от
  сообщения до письма в ящике завода и записей «Истории». Потом на проде в настоящей группе вместе с оператором: кнопки,
  файл в Claude на iPhone, фото бланка, кириллица в имени файла, отправка тестового письма себе.
