# Наша продукция в тендерах — дизайн

**Дата:** 2026-10-19 (ночь на 20.10). **Статус:** дизайн согласован с оператором в разговоре по частям (что считать нашей продукцией, что делать с найденным, объём, подход A, части 1–6), спеку просматривает оператор.

Третий пункт очереди оператора 2026-10-19 («отслеживание нашей продукции в тендерах»), вместе с пунктами бэклога «Мониторинг товаров сайта в тендерах», «Тендеры под запрос клиента» и «Планы закупок как ранний сигнал» (CLAUDE.md §16, «Идеи развития»).

## 1. Зачем

goszakup АИС смотрит только по 29 больницам ЗКО (импорт по реестру учреждений, CLAUDE.md §5). Тендеры по всей стране, где закупают то, что продаёт West-Med (товары westmed.kz: Фотек, Завод ЭМА, Аксион, Орион, НПП «Монитор»), видны только ручным поиском. Живой случай: запрос клиента на АСД-ФОТЕК (16.10) совпал слово в слово с ТЗ тендера ГМБ № 2 Астаны — нашли его вручную через API, когда приём уже закрывался; на площадке лот назван «Отсасыватель / для аспирации жидкого содержимого» (название из справочника ЕНС ТРУ), «Аппарат для аспирации дыма» — только в названии объявления, бренда нет нигде, а ТЗ — копия комплекта ФОТЕК («Блок аспирации», «пневмопедаль», «Шланг аспирационный, исполнение 3», «Держатель шланга аспирационного напольный»). Две попытки ЗЦП (02–06.10, 14–16.10) не состоялись, третья — «Из одного источника по несостоявшимся закупкам» 17802320-1 (16.10 19:32 – 20.10 09:00) — тоже нашлась только вручную.

Что значит «получилось»:
- о тендере по всей стране с нашим видом изделия АИС узнаёт в течение часа после публикации (тендеры живут 2–4 дня), заводит его в «Тендеры» и пишет в тему «Тендеры»;
- тендер, ТЗ которого списано с нашего товара или где назван наш бренд или модель, отмечен «★ точно наше» и приходит со звуком;
- видно, какие наши товары подходят к лоту, — со ссылкой на сайт;
- пункты планов закупок с нашими видами изделий (ещё не объявленные) видны заранее — страницей и сводкой раз в день;
- из частной заявки одной кнопкой видно, есть ли по стране тендер или план под позиции клиента (открытый, недавний или запланированный), с бюджетом заказчика и итогом.

Только рынок KZ (West-Med). Правит список групп администратор, смотрят все.

## 2. Решения разговора

| # | Вопрос | Решение |
|---|---|---|
| 1 | Что считать нашей продукцией | Виды изделий из нашего каталога (≈ 20 групп, список составлен по каталогу, правится на странице) + отдельная пометка «назван наш бренд / модель». Отвергнуты «только виды» и «только бренды» (бренды в лотах редки: за все годы — единицы лотов на бренд, за 2026 — ни одного). |
| 2 | Что делать с найденным | Заводить в «Тендеры» как обычный тендер (регион заказчика, отметка, фильтр «Наш товар»), дальше работают лоты, ТЗ, подбор, запрос цен, заявка, история. Отвергнуты «только сообщение» (завести тендер по номеру сейчас нечем) и «отдельный список с кнопкой Взять» (сложнее на день). |
| 3 | Объём | Полный: основа + страница правки списка + планы закупок + «Найти тендеры» из частной заявки, со спекой и планом (≈ 2,5–3 дня). |
| 4 | Планы закупок | Страница «Планы закупок» + сводка раз в день (тихо). Берём только пункты «Утверждён» (ещё не объявлены). |
| 5 | «Найти тендеры» | Открытые + закончившиеся за 90 дней (с итогом) + пункты планов. |
| 6 | Подход | A: поиск по словам групп на площадке (лоты и объявления по всей стране, ежечасно в рабочее время), своя проверка уточнений и исключений, найденное заводится тем же кодом, что импорт ЗКО. Отвергнут B «вся медицина страны в АИС» (тысячи тендеров в месяц, десятки тысяч запросов в сутки на токен, общий с продом, «Тендеры», забитые чужими закупками). |
| 7 | Точность | После поиска по виду — разбор ТЗ найденных лотов (нынешняя функция «ТЗ») и сверка с каталогом **по правилам**: наши бренды и модели, совпадение фраз с карточками наших товаров. Проверка Claude по ключу API — отвергнута сейчас (решение оператора), можно добавить отдельным блоком. |
| 8 | Звук | Сообщение, где есть хотя бы один «★», — со звуком; остальное — тихо, как вся тема «Тендеры». |
| 9 | Пересчёт | Пересчёт отметок (правка групп, первый запуск) — молча: Telegram только о том, что впервые нашли прогоны. |

## 5. Сопоставление (правила, без ИИ)

### 5.1 Текст и слова

Текст приводится к нижнему регистру, «ё» → «е», латинские двойники кириллицы (a, c, e, o, p, x, y, k, m, t, h, b) внутри кириллических слов → кириллица; знаки препинания — разделители. Слова групп сравниваются как в `MedicalGoodsVocabulary`: стем — начало слова, многословный терм — стемы рядом (окно ≤ 3 слова), «_» — подряд и в этом порядке. Бренды и модели (§5.3) — свой нормализатор кода модели.

### 5.2 Группа на лоте (`TYPE`)

Лот проходит группу, если:
1. в тексте лота (название + описание) есть одно из слов поиска группы — как целое слово площадки или как стем (площадка нашла по слову, у себя проверяем то же слово); у объявления с ОДНИМ лотом к тексту лота добавляется название объявления (так «аспирации» из «Аппарат для аспирации дыма» относится к лоту «Отсасыватель»); у объявления с несколькими лотами название объявления учитывается для лота, только если в его собственном тексте есть слово этой же группы;
2. уточнения (если заданы) — хотя бы одно в тексте лота + название объявления;
3. ни одного исключения в тексте лота (исключения проверяются по лоту, не по объявлению: «Закуп медицинских изделий» не должен отсекать лоты из-за слова в общем названии).

Группа «Наши бренды и модели» ставит сразу `NAMED` (§5.3).

### 5.3 Наш бренд или модель (`NAMED`)

Два списка:
- **бренды и модели группы** (столбец «Бренды и модели») засчитываются только у лота, который уже прошёл эту группу (`TYPE`): «орион» у озонового стерилизатора — наш, «орион» в произвольном лоте — нет (Orion Diagnostica и чужие «Орион»);
- **общий список** — у любого лота: бренды без двусмысленности (Фотек / Fotek, Аксион / Axion, ЭМАЛЕД, «НПП Монитор» фразой) и коды моделей каталога. «ЭМА», «Орион», «Монитор» в общий список не входят.

Коды моделей — из названий товаров каталога: слово, где есть и буквы, и цифры, и не меньше двух букв («ЭХВЧ-350-03», «ДКИ-Н-11», «ОБПЕ-450», «СК-36», «ЭК12Т-01»); сравнение — без пробелов, дефисов и точек, латинские двойники → кириллица («ЭХВЧ 350» = «ЭХВЧ-350»; код с исполнением «-03» засчитывается и без него). Общие обозначения, которые встречаются у любого производителя («2х15», «3х15», «150», «12-канальный»), моделью не считаются: у кода должна быть буквенная часть из каталога. Где искать: название и описание лота, название объявления, текст ТЗ (§7.4). Нашлось — `NAMED`, `evidence` «в ТЗ: ЭХВЧ-350» / «в названии лота: Фотек», `product_id` — товар с этим кодом (у бренда — пусто). Группа «Наши бренды и модели» (§4.1) ищет на площадке по словам общего списка, поэтому её находки сразу `NAMED`.

### 5.4 ТЗ списано с нашего товара (`COPIED`)

Фразы каталога строятся при загрузке каталога (§6) для каждого товара: из названия (части между «.», «,», «(», «–», «—», «;») и из описания и характеристик (строки, пункты списка, части через «;»). Фраза — 2–6 значимых слов подряд (служебные «для, с, и, в, на, по, из, к, от, до, не, более, менее, шт, мм, см, м» не считаются). Засчитывается только фраза, где есть хотя бы одно редкое для каталога слово — встречается не больше чем у 5 % товаров (то есть у ≤ 10 из 196); стоп-фразы, которые есть в любом ТЗ, не засчитываются никогда: «шнур питания», «сетевой кабель», «блок питания», «руководство по эксплуатации», «паспорт», «гарантийный талон», «инструкция по применению», «упаковка», «сумка для переноски» (список — константой рядом с правилом).

Сравнение с ТЗ: каждое слово фразы — по началу слова (первые 5 букв, короче — целиком), слова в том же порядке, между соседними — не больше одного другого слова («Шланг аспирационный» = «шланга аспирационного»). Оценка товара — число разных совпавших фраз; у семейства (товары одного бренда в одной группе) — объединение их фраз.

`COPIED`, если у одного товара или семейства совпало не меньше `COPY_MIN` фраз (стартовое значение 3) и в лоте есть наш вид (`TYPE` этой группы) или наш бренд. `evidence` — «совпало 5 фраз: блок аспирации; держатель шланга аспирационного напольный; …» (первые 4), `product_id` — товар с наибольшим числом совпадений (у семейства — его товар-набор, если есть, иначе лучший).

Порог и способ подсчёта (товар или семейство) выбираются калибровкой (§15.2): ложных `COPIED` на наборе — 0, Астана (17779323-1 и 17802320-1) — `COPIED` «Аппарат для аспирации дыма АСД-ФОТЕК».

### 5.5 Похожие наши товары

Для лота с отметкой — до трёх товаров каталога, ближайших по словам (оценка как у `ReplyMatcher`: доля веса слов товара, найденных в тексте лота + ТЗ, вес — редкость слова в каталоге), среди «товаров группы» — товаров, в названии которых есть слово поиска или бренд-модель группы, у «Наших брендов» — среди всего каталога. Оценка ниже 0,35 — не показывается.

### 5.6 Где хранится и когда считается

Сопоставление — чистые функции (вход: группы, каталог, текст лота, название объявления, текст ТЗ; выход: строки отметок). Пишет отдельный бин в своей транзакции (§6 CLAUDE.md: сеть — вне транзакции). Отметки, которых при пересчёте больше нет (лот перестал проходить группу после правки), удаляются; уровень тендера для Telegram не понижается.

## 6. Каталог сайта

Раз в сутки (по умолчанию 06:00 по Уральску, `PRODUCT_WATCH_CATALOG_CRON`) и кнопкой «Обновить» на странице «Наша продукция»:
- если заданы учётные данные сайта (`WESTMED_USERNAME` / `WESTMED_PASSWORD`, учётка ais@, уже на проде) — админ-API сайта: список `/api/admin/products` по 100 + карточка `/api/admin/products/{id}` только у новых и изменённых (`updatedAt`); в карточке — описание, характеристики, РУ. Публичную карточку `/api/v1/products/{slug}` НЕ звать — накручивает просмотры (CLAUDE.md §8 «Обращения»);
- иначе — публичный список `/api/v1/products?size=500` (название, бренд, раздел, краткое описание; без характеристик) — так работает локальная разработка без пароля сайта.

Новые — вставляются, изменённые — обновляются, пропавшие — `removed_at`. Фразы и коды моделей (§5.3–5.4) пересчитываются в памяти после каждой загрузки. Сбой — работает последний сохранённый каталог; на странице «Каталог сайта: 196 товаров, обновлён 19.10 06:00» (старше двух суток — жёлтым).

## 7. Поиск по стране (goszakup)

### 7.1 Расписание и выключатель

`PRODUCT_WATCH_ENABLED` (по умолчанию `false`) — выключатель всего блока: поиска, планов, каталога, отметок у импорта ЗКО и СК-Фармации, уведомлений. Расписание поиска — `PRODUCT_WATCH_CRON` (по умолчанию `0 30 8-19 * * MON-SAT`, через 20 мин после goszakup ЗКО), пояс — `PRODUCT_WATCH_ZONE` (по умолчанию Asia/Oral). Регистрация расписаний — как у `TenderAutoImportScheduler`: пусто — умолчание, «-» — выключено, опечатка — выключено с ERROR в логе, старт не роняет. Прогон — свой однопоточный исполнитель `product-watch`, `MarketContext.set(KZ)` в нём (§6 CLAUDE.md), идущий прогон не дублируется; кнопка «Искать сейчас» на странице «Наша продукция» (ADMIN) ставит прогон туда же.

### 7.2 Запросы

Для каждого слова включённых групп (слова повторяются между группами — запрашиваются один раз):
1. `Lots(filter:{nameDescriptionRu: слово, refLotStatusId: [190, 210, 220, 230, 240], lastUpdateDate: [сегодня − 60 дн, завтра]})` с вложенным `TrdBuy { id numberAnno nameRu orgBin totalSum publishDate endDate refBuyStatusId refTradeMethodsId systemId }`, по 200, не больше 5 страниц на слово (упор — WARN и строка в итоге);
2. `TrdBuy(filter:{commonName: слово, refBuyStatusId: [210, 220, 230, 240, 245], publishDate: [сегодня − 60 дн, завтра]})`, по 200, до 5 страниц.

Кандидат — объявление (номер), у которого срок (`endDate`, время площадки, UTC+5) позже «сейчас» по часам рынка и модуль госзакупа текущий (`systemId` = 3 или пусто). Пауза между запросами — 300 мс. Повторы — `UpstreamRetry` (как у импорта); 401 / 403 / 429 — прогон останавливается сразу, ошибка в итоге.

### 7.3 Заведение и обновление

Для каждого кандидата: лоты — `GoszakupClient.fetchLots` (v2, все страницы), сопоставление по §5.2–5.3 (без ТЗ). Ни один лот не прошёл — объявление пропускается (в АИС не заводится). Прошёл:
- объявления нет в АИС → заказчик (`fetchSubject`, кеш на прогон) → `GoszakupTenderWriter.upsertOne(d, subj, lots, null)` (регион — `RegionResolver` по заказчику), `found_by_product_search = true`;
- есть и заведено поиском → то же `upsertOne` (обновление статуса, срока, лотов);
- есть и заведено импортом ЗКО или СК-Фармации → не трогаем (его обновляет свой импорт), только отметки.

Отметки пишутся с `source = SEARCH`. Тендеры с `found_by_product_search`, приём которых по АИС ещё идёт (ACTIVE), но которых не было среди кандидатов прогона, — один запрос `TrdBuy(filter:{numberAnno})` на тендер: статус и срок обновляются (отменён / приостановлен / закрыт), лоты — нет. После срока тендер закрывает нынешний `TenderStatusScheduler`.

### 7.4 ТЗ найденных лотов

После записи: лоты с отметкой (любого источника), у которых ТЗ ещё не сверено (`spec_checked_at` пусто), статус ТЗ не терминальный (`NO_FILE`, `UNREADABLE`) и попыток меньше 3, — не больше `PRODUCT_WATCH_SPEC_PER_RUN` (по умолчанию 10) за прогон, сначала лоты тендеров с ближайшим сроком:
1. попытка отмечается ДО разбора (`tech_spec_attempts + 1`, статус `ERROR`) — урок `TechSpecBackfillScheduler` (§8 CLAUDE.md: exit 137 не ловится никаким `catch`);
2. разбор — `TechSpecService.parse(lotId)` (goszakup и СК-Фармация, PDF → русская часть → `required_spec`), исход — той же схемой, что у фоновой очереди (`NotFoundException` → `NO_FILE`, `UnprocessableException` → `UNREADABLE`, сеть → `ERROR`); общий код разбора с исходом выносится из `TechSpecBackfillScheduler.processOne` в отдельный бин и используется обоими;
3. ТЗ разобрано (или уже было `OK`) → сверка §5.3–5.5 по тексту ТЗ → уровень, `evidence`, похожие товары, `spec_checked_at`;
4. ТЗ недоступно (`NO_FILE` / `UNREADABLE` / 3 неудачи) → `spec_checked_at` ставится, отметка остаётся по названию (`TYPE` или `NAMED`), в карточке «ТЗ недоступно».

Если ТЗ уже было разобрано раньше (кнопкой «ТЗ» или очередью) — скачивания нет, только сверка.

### 7.5 Итог прогона и сбои

Итог (`ProductWatchSummary`, как `ImportSummary`): слов, запросов, кандидатов, новых тендеров, обновлено, отмечено лотов (по уровням), ТЗ сверено, ошибок + последняя ошибка. Виден на странице «Наша продукция» («Поиск по стране: сегодня 10:30 — найдено 2 новых, ★ 1, ошибок 0») и в логе одной строкой INFO. Два прогона подряд с ошибками и без единой записи → `ImportOutageNotifier.afterRun("поиска нашей продукции", …)` — «⚠️ Поиск нашей продукции не работает …», затем «✅ снова работает» (механизм и порог — те же, что у импорта).

## 8. Отметки у тендеров ЗКО и СК-Фармации, пересчёт

- **Импорт ЗКО и СК-Фармации** (при включённом блоке): в конце прогона, в его же потоке и под рынком KZ, — сопоставление §5.2–5.3 по лотам созданных и обновлённых тендеров (`ImportSummary` получает список затронутых номеров — `touchedExtIds`, рядом с `createdExtIds`), `source = IMPORT`. Без запросов к площадке. ТЗ таких лотов сверяет ближайший поиск по стране (§7.4).
- **Пересчёт** — после сохранения групп на странице и при старте бэкенда с включённым блоком (идемпотентно, без запросов к площадке): все тендеры рынка KZ с открытым приёмом (ACTIVE, срок не прошёл) — сопоставление по названиям и уже разобранным ТЗ, `source = REMATCH`, молча (§9): у тендеров, где до пересчёта отметок не было вовсе, `product_notified_level` ставится равным новому уровню. Тендеры, которые уже ждут сообщения (отметка поиска или импорта, сообщение не ушло — сбой Telegram перед рестартом), пересчёт не «гасит».

## 9. Уведомления (Telegram)

- Тема «Тендеры» (`TELEGRAM_TENDERS_THREAD_ID`), одно сообщение на прогон (поиск по стране, импорт ЗКО, импорт СК-Фармации).
- Кого: тендеры, у которых уровень отметки выше `product_notified_level` (пусто — ниже любого), поставлен прогоном (`SEARCH` / `IMPORT`, не `REMATCH`), статус ACTIVE и приём не закончился (`ImportDeadline.passed` по часам рынка). После отправки — `product_notified_level` = уровень, `product_notified_at`. Первое сообщение о тендере — полное; повышение `TYPE` → `COPIED` / `NAMED` позже — короткое «★ Уточнение: ТЗ списано с нашего товара …» (обычно ТЗ сверяется в том же прогоне, и уточнений почти не будет).
- Звук: сообщение, где есть хотя бы один тендер уровня `NAMED` / `COPIED`, — со звуком (`TelegramClient.sendTenders(text, silent)`), иначе тихо.
- Текст (`ProductWatchComposer`, чистая функция, ≤ 3500 символов, все поля — `TelegramText.oneLine`):

  Лоты — только наши (до трёх, «и ещё N наших лотов»); способ закупки — если не обычный ЗЦП («из одного источника», «конкурс», «аукцион», «электронный магазин»). Не помещается — «…и ещё N — фильтр «Наш товар» в АИС: …/tenders?our=ANY&market=KZ».

## 10. Планы закупок

### 10.1 Сбор

Раз в день (`PRODUCT_WATCH_PLANS_CRON`, по умолчанию `0 30 7 * * MON-SAT`, тот же выключатель), в том же исполнителе `product-watch`, что поиск (последовательно — два прогона не нагружают токен одновременно), `MarketContext.set(KZ)`:
1. для каждого слова включённых групп — `Plans(filter:{nameDescriptionRu: слово, plnPointYear: [этот год, следующий], refPlnPointStatusId: [2]})` с `RefUnits`, `RefTradeMethods`, `RefMonths`, `PlansKato { fullDeliveryPlaceNameRu }`, `Customer { bin nameRu }`, по 200, до 5 страниц;
2. услуги отсекаются: единица со словом «услуг», или название с маркером услуги (`MedicalGoodsVocabulary.SERVICE_STRONG` — «услуг», «ремонт», «обслуживан», «поверк»…);
3. проверка группы — как у лота (§5.2), текст — название + описание + дополнительное описание; бренд или модель (§5.3) → `NAMED`;
4. запись: новый пункт — вставка (`first_seen_at`), известный — обновление (`last_seen_at`, поля); регион — `RegionResolver` по месту поставки, иначе по названию заказчика;
5. пункты рынка, которые были «Утверждён», но не встретились в сборе: батч `Plans(filter:{id:[…]})` (по 200) → статус сменился — `gone_at`, `gone_status`; не нашёлся вовсе — `gone_status` «снят».

Нагрузка — около 100–150 запросов в день.

### 10.2 Страница «Планы закупок»

Группа меню «Тендеры», после «Поиска тендеров» (видят все). Строка пункта: месяц закупки («ноябрь 2026», прошедший — «сентябрь 2026 · месяц прошёл»), заказчик · регион, что закупают (название, описание свёрнуто), «4 шт. × 1 480 000 = 5 920 000 ₸», способ, группа, ★. Фильтры: группа, регион, «ближайшие 3 месяца», «новые за 7 дней», «показать объявленные и снятые» (по умолчанию — только «ждут объявления»), поиск по тексту; сортировка: по месяцу (по умолчанию), по сумме, сначала новые. До 500 строк. На телефоне — карточки (`responsive-cards card-grid`, §12 CLAUDE.md). На РФ — «Только для Казахстана».

```
…и ещё 4 — «Планы закупок» в АИС: …/procurement-plans?fresh=1&market=KZ
```

Сверху ★, дальше по сумме, не больше 10. Первый сбор после включения — молча (`digested_at` ставится всем найденным): иначе первое сообщение было бы о сотнях пунктов.

## 11. «Найти тендеры» в частной заявке

### 11.1 Поиск

Кнопка «Найти тендеры по стране» в разделе позиций заявки (KZ; видят все — поиск только читает площадку). Фоновая задача на заявку (один поиск на заявку одновременно; повторное нажатие во время поиска — его статус); поиски разных заявок идут по одному в своём однопоточном исполнителе `tender-search` (очередь — «ждёт: идёт поиск по другой заявке»), чтобы не нагружать токен параллельно. Прогресс «позиция 3 из 8», результаты живут в памяти 1 ч («Искать заново»).

1. Позиции — до 10 (по порядку). Слова позиции — одно-два: если позиция проходит группу (§5.2 по её названию и бренду) — слова поиска этой группы; иначе — самые длинные слова названия длиннее 4 букв, кроме общих («аппарат», «система», «набор», «комплект», «медицинский», «изделие», «прибор», «устройство», «для»…). Позиция без годного слова — «не по чему искать».
2. По каждому слову: `Lots(filter:{nameDescriptionRu, lastUpdateDate: [сегодня − 90 дн, завтра]})` (любой статус, до 2 страниц по 200); `TrdBuy(filter:{commonName, publishDate: [сегодня − 90 дн, завтра]})` (до 1 страницы) + лоты найденных объявлений (`Lots(filter:{trdBuyNumberAnno})`, не больше 5 объявлений на слово); `Plans(filter:{nameDescriptionRu, plnPointYear: [этот, следующий], refPlnPointStatusId: [2]})` (1 страница).
3. Состояние кандидата: «приём до …» (открыт: статус лота 190–240 и срок позже «сейчас»), «не состоялся ДД.ММ» (370), «состоялся ДД.ММ» (360), «отменён» (410 / 430), «план: ноябрь 2026».
4. Похожесть кандидата на заявку — по словам (как §5.5): текст позиций (название, бренд, характеристики) против текста лота (название, описание, название объявления) / пункта плана; ниже 0,35 — отбрасывается.
5. ТЗ: у 10 лучших тендеров (открытых и закончившихся) — разбор ТЗ без записи в АИС (`fetchLotTechSpec` + `downloadFile` + `PdfTextExtractor` + `TechSpecExtractor.russianSection`; лот уже в АИС с разобранным ТЗ — его `required_spec`) и сверка с ВСЕМИ позициями заявки: доля позиций, чьё название (как фраза §5.4) встречается в ТЗ. Список клиента из 8 позиций против ТЗ Астаны — «совпали позиции 1–8 (ТЗ)».
6. Нагрузка — около 30–60 запросов за нажатие; пауза 300 мс; 401 / 403 / 429 — поиск останавливается с текстом причины.

### 11.2 Результат

Список тендеров и пунктов планов, лучшие сверху (сначала совпадение по ТЗ, потом похожесть), не больше 15:

```
не состоялся 16.10 · совпали позиции 1–8 (ТЗ)
ГКП на ПХВ «Городская многопрофильная больница № 2» · г. Астана
Отсасыватель — 1 шт. · 3 714 285,71 ₸ за ед.
goszakup № 17779323-1 ↗ · Итоги › · Завести в АИС · В историю сделки
```

- «↗» — объявление на портале (та же ссылка, что у карточки тендера); «Открыть в АИС», если тендер уже в АИС.
- «Итоги ›» (у «состоялся») — `Contract(filter:{trdBuyNumberAnno})` + название поставщика (`/v2/subject/biin`): «победитель: ТОО «…», договор 3 650 000 ₸ от 12.09»; пусто — «договор ещё не опубликован».
- «Завести в АИС» (ADMIN) — тем же кодом, что поиск по стране (§7.3), с отметками; после — «Открыть в АИС».
- «В историю сделки» (ADMIN) — заметка в ленту заявки (`DealEventService.note`): «Запрос клиента совпадает с тендером 17779323-1 (ГКП на ПХВ «Городская многопрофильная больница № 2», г. Астана) — не состоялся 16.10».
- Пункт плана — «план: ноябрь 2026 · КГП «…» · Карагандинская обл. · Аспиратор — 2 шт. · 1 200 000 ₸» (без кнопок, кроме «в АИС: Планы закупок»).

Результаты в базу не пишутся (кроме заведённого и заметки).

## 12. Экраны

### 12.1 «Наша продукция» (`/product-groups`, группа меню «Тендеры», после «Планов закупок»)

- Строка поиска: «Поиск по стране: включён · сегодня 10:30 — найдено 2 новых, ★ 1, ошибок 0 · Искать сейчас» (ADMIN; выключен — «выключен — PRODUCT_WATCH_ENABLED»).
- Группы карточками (порядок `position`): название, слова поиска, уточнения, исключения, бренды и модели (чипы), «вкл / выкл»; правка на месте (ADMIN), «↑ ↓», «Удалить» (с подтверждением в странице), «+ Группа»; «Сохранить» — весь список одним запросом (как «Шаблоны ответов»), после сохранения — пересчёт отметок (§8) и тост «Сохранено; отметки пересчитаны: N тендеров».
- У группы «Проверить» (ADMIN): запросы §7.2 по её словам (до 2 страниц на слово) → список лотов с идущим приёмом: «прошёл — по слову … / не прошёл: нет уточнения / исключение «сварочн»», число найденных площадкой и прошедших; проверяются несохранённые значения карточки.
- Внизу: «Каталог сайта: 196 товаров (Фотек 84, Завод ЭМА 44, Аксион 31, Орион 23, НПП Монитор 14), обновлён 19.10 06:00 · Обновить».
- Оператор видит всё без кнопок правки. На РФ — «Только для Казахстана».

### 12.2 «Тендеры»

- Карточка тендера в списке — чип уровня: «★ наш товар: Фотек» (`NAMED` / `COPIED`, текст — бренд или товар), «🏷 наш вид: отсасыватель» (`TYPE`, текст — группа или слово); тон чипа — по kit (`--success` для ★, `--accent` для 🏷).
- Фильтр «Наш товар»: все / ★ точно наше / любой наш вид / группа (список групп); параметр адреса `our=` (ссылка из Telegram открывает список с фильтром).
- Данные для списка — сводка отметок одним запросом на все тендеры списка (без N+1): `TenderResponse.ourProduct {level, label, groups}`.

### 12.3 Карточка тендера

- В шапке у заведённых поиском — «Найден поиском по нашей продукции»; способ закупки, если не ЗЦП.
- У лота — чипы отметок (как в списке) и строка: «★ ТЗ списано с нашего товара: Аппарат для аспирации дыма АСД-«ФОТЕК» ↗ — совпало 5 фраз: …» / «★ в ТЗ: ЭХВЧ-350» / «похоже: ЭК12Т-01-«Р-Д» ↗, ЭК3ТЦ-3/6-04 ↗»; «ТЗ недоступно», если так. Ссылка ↗ — товар на сайте, тем же видом, что у позиций заявки (`{сайт}/product/{slug}`, `WestmedLeadMapper.productUrl` — общий помощник); это ссылка, а не запрос АИС: просмотр засчитывается, только когда её открывает человек. `TenderLotResponse.productMatches[]`.

### 12.4 «Планы закупок» — §10.2. «Найти тендеры» — §11.2, панель под позициями заявки (на телефоне — во весь экран).

Все новые страницы — ленивые (`loadComponent`), начальный бандл не растёт сверх текущего (1,40 МБ при пределе 1,5 МБ; чипы и фильтр «Тендеров» — в начальном, они малы).

## 13. API

- `GET /api/product-groups` → `{groups:[…], catalog:{count, byBrand, syncedAt, stale}, watch:{enabled, running, lastFinishedAt, lastSummary}}`; `PUT /api/product-groups` (ADMIN) — весь список (проверка до записи: название 1–120, слова 1–10 по ≤ 40 без пробелов, уточнения/исключения/бренды ≤ 30 по ≤ 40; пусто — 400 с текстом) → список + число пересчитанных тендеров; `POST /api/product-groups/probe` (ADMIN, тело — группа) → `{found, passed, lots:[{numberAnno, lotName, customer, region, deadlineAt, passed, reason}]}`; `POST /api/product-watch/run` (ADMIN) → статус; `GET /api/product-watch/status`; `POST /api/site-catalog/sync` (ADMIN) → `{count, added, updated, removed}`.
- `GET /api/tenders` — у тендера `ourProduct` (§12.2); `GET /api/tenders/{id}/lots` — у лота `productMatches`.
- `GET /api/procurement-plans?group=&region=&soon=&fresh=&all=&q=&sort=&limit=` (рынок KZ, иначе пусто); `POST /api/procurement-plans/collect` (ADMIN) → статус.
- `POST /api/private-requests/{id}/tender-search` → статус (запуск или текущий); `GET /api/private-requests/{id}/tender-search` → `{running, progress, total, startedAt, error, results:[…]}`; `POST /api/goszakup/announcements/{numberAnno}/import` (ADMIN) → `{tenderId}`; `GET /api/goszakup/announcements/{numberAnno}/result` → `{status, supplierName, supplierBin, contractSum, signDate}`; «В историю сделки» — прежний `POST /api/private-requests/{id}/events` (NOTE).
- Гард рынка — как везде (§6 CLAUDE.md): пути по id заявки — `PrivateRequestService.findById`; всё — только KZ (РФ — 400 «Только для Казахстана» на запись, пусто на чтение).

## 14. Нагрузка на токен goszakup

Токен общий с продом и с разработкой (память `goszakup-prod-ip-blocked`: 11.10 после ≈ 2 тыс. запросов прогона — 403 на час). Оценка: поиск по стране — 80–120 запросов за прогон × 12 = 1–1,5 тыс. в сутки; планы — 100–150 раз в день; «Найти тендеры» — 30–60 за нажатие; ТЗ — 2 запроса на лот, до 10 лотов за прогон. Пауза 300 мс между запросами каждого фонового прогона; 401 / 403 / 429 — остановка без повторов. Для разработки — отдельный токен (перевыпуск — оператор, «Профиль участника → Выпуск токена»); без него локальные проверки — малыми порциями (одна группа, «Проверить», один прогон).

## 15. Проверка

### 15.1 Тесты

- Сопоставление (§5) на настоящих текстах: группы, уточнения и исключения (уличный светильник / операционный, сварочный электрод / нейтральный, лабораторный дозатор / шприцевой, компьютерный монитор / монитор пациента, «Стойка-ресепшн»), одно- и многолотовые объявления (название объявления), бренды и модели в разных написаниях («ЭХВЧ 350», «ЭХВЧ-350-03», латинские двойники), «2х15» — не модель, «Орион» без уточнения — не наш.
- Запросы площадки — на записанных ответах (данные госзакупок публичные, обезличивать не нужно): окно дат, статусы, страницы, упор в 5 страниц, 403 — остановка, пауза.
- Заведение и обновление тендеров (`found_by_product_search`, регион, обновление «пропавшего» по номеру), отметки ЗКО и СК-Фармации, пересчёт (молча, удаление лишних отметок).

- Планы: только «Утверждён», услуги отсекаются, «объявлен / снят», первый сбор молча, сводка (★ сверху, ≤ 10).

### 15.2 Гейт сверки ТЗ

Набор — 30–40 настоящих ТЗ лотов, найденных поиском по стране по всем группам (тексты русской части — в `src/test/resources/product-watch/specs/`, разметка «COPIED / NAMED / TYPE и товар» — `golden.tsv`, размечается вручную по ТЗ и каталогу, Астана — оба объявления), и снимок каталога (`site-catalog.json`, данные сайта). ## 17. Известные ограничения

- Находим только то, где заказчик употребил одно из наших слов в той же форме (лот назван по ЕНС ТРУ; «Аппарат для аспирации дыма» ловится словом «аспирации» в описании и в названии объявления, а «Аспиратор дыма» — нет). Промахи видны через «Проверить» и правятся словами группы.
- `COPIED` ловит ТЗ, взятые у нашего производителя (частый случай); ТЗ своими словами остаются `TYPE` — решение по ним за оператором.
- Только goszakup и СК-Фармация; СК-Фармация — по своей ленте (окно `SKPHARMACY_MAX_PAGES`), без поиска по слову (у портала нет API).
- Регион у СК-Фармации — организатора («г. Астана»).
- Результаты «Найти тендеры» не сохраняются (час в памяти).
- Сканы ТЗ (PDF без текста) — «ТЗ недоступно» (`UNREADABLE`).
