# Готовое КП — занести в АИС с ценами — дизайн

**Дата:** 2026-10-19. **Статус:** дизайн согласован с оператором в разговоре по частям, спека ждёт его ревью.

**Подпроект 3а** темы «Жизненный цикл сделки» (CLAUDE.md §16, первый пункт). Подпроект 3 «Частники после КП» разбит на куски (решение оператора 2026-10-19), порядок:
- **3а — готовое КП** — этот документ;
- 3б — этапы после «Согласился»: договор / счёт → оплата клиента → заказ и оплата поставщику → поставка → закрыто, причина проигрыша (3д) — внутри;
- 3г — напоминания;
- 3в — документы из КП (договор, счёт, накладная) — нужен ли, решится вопросом «где сейчас делают договор и счёт: 1С или Word» при 3б.

## 1. Зачем

КП, сделанное не в конструкторе (Word отца, КП по образцу поставщика — Аксион для Казыгуртской ЦРБ 15.10, консоли «ОЗОН» для Казталовской РБ 16.10, «Элема-Н»), в АИС отметить нечем: этап сделки «КП отправлено» считается только по КП из конструктора. Слова оператора (2026-10-15): «просто файл не закрепляет цены, которые дали» — записать надо, **по какой цене предложили каждую позицию и итог**.

Что значит «получилось»:
- готовое КП занесено в сделку файлом и строками: что предложено, цена клиенту каждой позиции, итог — и итог совпадает с документом;
- сделка стоит на этапе КП, дальше — как с КП из конструктора («Согласился / Отказался», журнал, история, прибыль по закупке);
- КП, ушедшее клиенту письмом с info@ или в WhatsApp, АИС замечает в переписке сама и предлагает занести (идея оператора 2026-10-19: «если в переписке есть что-то типа „высылаем КП“ — что вот мы КП отправили»).

Работают оператор и отец, позже менеджеры; с компьютера и с телефона. Записи — только админ, оператор всё видит (как везде в АИС). Рынки — оба (модель общая), переписка есть только у KZ.

## 2. Решения разговора

| # | Вопрос | Решение |
|---|---|---|
| 1 | С какого куска подпроекта 3 начать | 3а — готовое КП. |
| 2 | В каком виде КП | По-разному: Word / Excel разбираются сами, PDF и картинка — цены вписываются рядом со страницами. |
| 3 | Как устроить | Готовое КП — обычное «КП клиенту» (`client_offer`) с приложенным файлом: этапы, «Дальше», журнал, история, закупка и прибыль, будущие 3б / 3в работают без второго вида КП. Отдельная сущность «КП со стороны» и «только файл и итог» отклонены. |
| 4 | Подсказка из переписки | Только предлагать, решает человек одной кнопкой; ошибочную подсказку скрывает «Не КП». Сам статус по переписке не меняется. |

## 3. Как это выглядит

### 3.1 Где

На странице заявки, раздел «КП клиенту»: рядом с «Создать КП клиенту» — «Занести готовое КП» (только админ). Сделка, начатая вне АИС (КП для больницы сделали сразу), заводится как обычно — «+ Новая заявка», — и в ней «Занести готовое КП»: позиции заявка получит из строк КП (раздел 4.3).

### 3.2 Окно «Готовое КП»

```
Готовое КП                                                          ✕
  ◉ Из переписки            ○ С компьютера
    15.10 12:30 · письмо «Коммерческое предложение» → crb@…
        📎 КП West-Med 15.10.2026 – Аксион, Казыгуртская ЦРБ.pdf       похоже на КП
    14.10 18:02 · WhatsApp → +7 701 …   📎 КП ВитаЛайн.docx              занесено: КП № 24
  Статус:  ◉ Отправлено  [15.10.2026]     ○ Клиент уже согласился
                                                       [Отмена] [Занести]
```

- **Из переписки** — файлы наших писем с info@ и наших сообщений WhatsApp в переписке сделки (раздел 5.3), новые сверху; у файла — «похоже на КП» (признаки раздела 3.4), «занесено: КП № N» (уже занесён — выбрать можно, получится второе КП), «это КП № N из АИС» (PDF самой АИС — занести нельзя, вместо этого «Отметить КП № N отправленным»). Дата «Отправлено» — дата сообщения. Сделки без переписки (не из обращения, обращение с сайта или звонок) — только «С компьютера».
- **С компьютера** — Word (.docx, .doc), Excel (.xlsx, .xls), PDF, картинка (jpeg, png, webp, gif), до 15 МБ. Дата «Отправлено» — сегодня, правится.
- **Статус:** «Отправлено ДД.ММ.ГГГГ» (умолчание) или «Клиент уже согласился» (КП сразу «Принято»; дата отправки та же).
- **Номер и дата КП** в окне не спрашиваются — берутся из документа (раздел 4.4) и правятся в шапке КП; номера в документе нет — КП без номера («КП от 24.09.2026»), счётчик «исх. №» не трогается.
- После «Занести» — сразу редактор этого КП.

### 3.3 КП из файла — тот же редактор `/client-offers/:id`, режим «из файла»

```
КП от 24.09.2026 · из файла · Отправлено 24.09                   ⋯
┌ Из файла «КП West-Med 24.09.2026.docx» · 44 позиции · итог 20 417 347,00 = «ИТОГО» в файле ✓ ┐
│ Шапка: №, дата, клиент, «Кому», предмет            │  Документ                         │
│ Позиции: наименование · кол-во · ед. · цена клиенту │  таблица файла / страницы PDF /   │
│          · НДС · закупка · прибыль                 │  картинка          [Скачать файл] │
│ Маржа «только для вас»                             │                                   │
└────────────────────────────────────────────────────┴───────────────────────────────────┘
[Скачать файл] [Поделиться] Статус ▾          без закупки: 3 · не зарегистрировано: 2
```

- **Шапка** — как у «Создать КП клиенту»: клиент — учреждение заявки, «Кому» — учреждение → название клиента → контактное лицо; номер и дата — из документа (раздел 4.4), всё правится.
- **Строка сверки** над формой: «Из файла «…» · N позиций · итог X = «ИТОГО» в файле ✓»; не совпало — «итог по строкам X ≠ Y в файле — проверьте строки» (тон предупреждения); итога в файле нет — «Итога в файле нет — итог по строкам X; если это варианты на выбор, удалите лишние строки, когда клиент выберет»; PDF или картинка — «Цены впишите по документу справа»; файл не разобран — причина и «впишите цены по документу». Считается при каждом чтении — правка строк сразу видна в сверке.
- **Позиции** — тот же компонент строк, что у конструктора: цена клиенту — из файла (это ручная цена строки), наценка выводится обратно от закупки; строка без цены клиенту остаётся без цены (у КП из файла цена от наценки не считается — раздел 4.5); «Поставщик ▾», закупка, прибыль, метка РУ — как у КП из заявки. «↺ вернуть расчёт» у цены — нет.
- **Нет блоков** «Цены» (общая наценка, округление, НДС вкл / выкл), «Условия», «Оформление»; предпросмотр страницами заменён документом (таблицы файла как в файле, страницы PDF, картинка).
- **Нижняя панель:** «Скачать файл» (исходный файл), «Поделиться» (тот же файл в окно отправки телефона), статус; предупреждения «без закупки: N», «не зарегистрировано: N» — как сейчас.
- **«⋯»:** «Дублировать» — КП **в конструкторе** с этими строками и ценами (ручные цены), номер из счётчика: так готовое КП отца переезжает в конструктор; «Удалить» — КП из файла удаляется в любом статусе (занесли не тот файл), с подтверждением.

### 3.4 Подсказка из переписки

В «Дальше» на странице заявки, пока у сделки нет отправленного или принятого КП (этапы «Пустая», «Новая», «Запрошены цены», «Есть цены», «КП — черновик», «КП отклонено»), подсказка заменяет обычное «Дальше»:

- **Наш файл похож на КП** → «Похоже, КП ушло клиенту 15.10 письмом — «КП West-Med … .docx» **[Занести КП]** · Не КП» («письмом» / «в WhatsApp» — по каналу сообщения). «Занести КП» открывает окно 3.2 с этим файлом и датой; «Не КП» — подсказка про этот файл больше не появляется.
- **PDF самой АИС** («КП № 481 от 07.10.2026 – …»), а КП № 481 этой сделки с той же датой — черновик → «КП № 481 ушло клиенту 15.10 письмом — **[Отметить отправленным]** · Нет». «Отметить» ставит КП «Отправлено» временем сообщения; «Нет» — как «Не КП».

**Признаки «похоже на КП»** — у файла нашего сообщения (письмо из «Отправленных» info@ или сообщение WhatsApp с нашего номера) в переписке сделки:
- файл — PDF, Word или Excel, сохранён (не «больше предела»);
- в теме письма, тексте сообщения (без цитаты) или имени файла есть «КП» или «KP» отдельным словом, «коммерческ… предложени…» или «ценов… предложени…» («Высылаем КП», «Коммерческое предложение West-Med», «КП_West-Med_15.10.docx»);
- файл ещё не занесён ни в одно КП, не отмечен «Не КП» и не является PDF самой АИС с КП этой сделки в другом статусе.

Несколько подходящих — подсказка про самый поздний. Подсказка только в «Дальше» страницы заявки (в списке заявок — нет). Оператор видит её текст без кнопок.

### 3.5 Дальше — как с обычным КП

- Этап «КП отправлено» → «Согласился / Отказался»; «Клиент уже согласился» в окне — сразу «КП принято».
- Журнал «КП клиентам» — метка «из файла»; поиск — как у всех КП.
- История сделки: «КП № 24 занесено из файла «КП West-Med 24.09.2026.docx»» (автор) и «КП № 24 отправлено» (время отправки); согласие при занесении — событие «КП № 24: клиент согласился», как у смены статуса.
- Шаг «КП» строки этапов: «№ 24 · отправлено 15.10» / «от 24.09 · отправлено 15.10» (без номера).

### 4.1 Какие таблицы

Читаются **все** таблицы документа (листы Excel), у которых шапка с наименованием и ценой или суммой — по тем же правилам шапки, что ответы поставщиков (`ReplyTableReader`); таблица на нескольких страницах склеивается, как сейчас. Таблицы без цены (характеристики, «Наличие разрешительной документации», «Тип ротора» центрифуги) не берутся. Ответы поставщиков по-прежнему берут одну лучшую таблицу — правило «все таблицы» только у КП.

### 4.2 Вид строки

По порядку:
1. **Один и тот же текст во всех непустых ячейках строки** (объединённая во всю ширину: «1 этаж», «Основные комплектующие:», «Запас») → **раздел** (`SECTION`), цена не читается.
2. **Цены нет, а текст «включено» / «включено в стоимость»** («Гарантия… — Включено в стоимость», «Включено в стоимость медицинской техники») → **«включено»** (`INCLUDED`).
3. **Цена есть** (цена за единицу или сумма / количество — `ReplyRowValues`) → **позиция** (`ITEM`): наименование (с артикулом и брендом, если у них свои колонки), количество (нет — 1), единица (нет — «шт»), цена клиенту с НДС, как в документе → ручная цена строки (`price_override`); ставка НДС — из колонки «НДС» / «Ставка НДС» («В том числе НДС 5%», «16 %», «Без НДС»), если такая ставка есть в списке рынка, иначе — по метке РУ связанной позиции (раздел 4.3) или ставкой новой строки рынка.
4. **Остальные строки с текстом без цены** → раздел; пустые — пропуск.

**«ИТОГО» / «Всего» / «Итог»** — конец таблицы, как сейчас; число этой строки (из колонки суммы, иначе последнее число строки) — **итог файла**; у нескольких таблиц итог файла — сумма их итогов. Строки после «Итого» («в т. ч. НДС…») не читаются.

**Валюта** — по правилам ответов поставщиков (таблица, затем текст вне таблицы); не валюта рынка КП или «валюта не ясна» → цены клиенту не ставятся, строка сверки: «Цены в файле — в руб., а КП — в тенге: впишите цены по документу».

### 4.3 Позиции заявки

- **В заявке нет позиций** → позиции заводятся из строк-позиций КП: наименование (≤ 255), количество (дробное или больше предела `Integer` — пусто, «кол-во уточняется»), единица, бренд (если есть колонка); строки КП связываются со своими позициями. Так сделка, начатая вне АИС, получает позиции для этапа «Позиции».
- **Позиции есть** → строки-позиции КП сопоставляются с позициями заявки тем же сопоставлением, что ответы поставщиков (`ReplyMatcher`, те же пороги: уверенная пара — оценка ≥ 0,60 и отрыв ≥ 0,15; принцип «лучше не связать, чем перепутать»). Связанная строка получает `tender_lot_id`, закупку — лучший ответ поставщика по позиции (правило `PurchaseOffers.best`, как «Создать КП клиенту»), поставщика и ссылку на ответ, метку РУ позиции (как «Создать КП клиенту»: подтверждённое РУ — текст, производитель и страна из реестра). Несвязанная строка — строка КП без позиции (закупку можно вписать руками, «Поставщик ▾» у неё нет). Позиции, которых нет в КП, ничего не получают. Новых позиций в заявку при этом не добавляется.

### 4.4 Номер и дата КП

Из текста документа над первой таблицей (абзацы Word, ячейки Excel выше шапки, текст первой страницы PDF — PDFBox): «Исх. № 24 от 17 апреля 2026 г.», «Исх № 24 от 17.04.2026», «КП № 481 от 07.10.2026», «Коммерческое предложение № 5 от …», «Дата: 24.09.2026 г.». Номер — только после «Исх», «КП» или «Коммерческое предложение» («ГКП на ПХВ «Городская поликлиника № 5»» номером КП не считается); дата — после номера («от …») или после «Дата:»; форматы ДД.ММ.ГГГГ и «17 апреля 2026». Нет номера — КП без номера; нет даты — дата КП = дата отправки из окна.

### 4.5 Расчёт КП из файла

Тот же `ClientOfferCalculator`, одно отличие: **у КП из файла цена строки берётся только из ручной цены**; строка без неё — без цены (сумма, НДС и прибыль пусты), закупка показывается. Общая наценка, округление и «наценка строки» у КП из файла не действуют. НДС «в т. ч.» — по ставке строки; итог — сумма строк с ценой.

### 4.6 PDF и картинка

Таблиц не читаются (разбора PDF нет — CLAUDE.md §16). Строки КП — из позиций заявки, как «Создать КП клиенту», но **без цены клиенту**: оператор вписывает цены, глядя на страницы справа. Позиций нет — КП без строк, строки добавляются вручную. Итога файла нет — сверка «Цены впишите по документу». Номер и дата — по тексту первой страницы (4.4), если PDF текстовый.

### 4.7 PDF самой АИС

Имя файла или текст первой страницы — «КП № N от ДД.ММ.ГГГГ», и в **этой** сделке есть КП из конструктора с этим номером и датой → это не готовое КП, а документ конструктора: занести нельзя (400 «Это КП № 481 из конструктора — …»). Что предлагается вместо: КП № N — черновик → «Отметить КП № 481 отправленным» (в окне и подсказкой); уже отправлено, принято или отклонено → только текст «КП № 481 уже отправлено 07.10». Такого КП в сделке нет (другая сделка, удалено) — обычный файл, заносится как готовое КП.

## 5. Данные (V33)

### 5.1 `client_offer`

```sql
ALTER TABLE client_offer ADD COLUMN origin VARCHAR(10) NOT NULL DEFAULT 'BUILDER';   -- BUILDER / FILE
ALTER TABLE client_offer ALTER COLUMN number DROP NOT NULL;                          -- пусто — только у FILE
```

- `origin = FILE` — готовое КП; у конструктора номер по-прежнему обязателен (проверка в сервисе: создание, копия, PUT).
- Подпись КП там, где сейчас «КП № N» (лента, этапы, «Дальше», тексты событий, имя файла, журнал, шапка редактора): номер есть — «КП № 24», нет — «КП от 24.09.2026». Один помощник на сервере и один на фронте.

### 5.2 `client_offer_file`

```sql
CREATE TABLE client_offer_file (
    id                  BIGSERIAL PRIMARY KEY,
    offer_id            BIGINT       NOT NULL UNIQUE REFERENCES client_offer (id) ON DELETE CASCADE,
    file_name           VARCHAR(255) NOT NULL,
    mime_type           VARCHAR(100),
    size_bytes          BIGINT       NOT NULL,
    sha256              CHAR(64)     NOT NULL,
    content             BYTEA        NOT NULL,
    kind                VARCHAR(10)  NOT NULL,   -- EXCEL / WORD / PDF / IMAGE (ReplyFileKind)
    parse_status        VARCHAR(12)  NOT NULL,   -- PARSED / NO_TABLE / NOT_PARSED / FAILED / TOO_LARGE (ReplyParseStatus)
    parse_note          TEXT,
    tables              JSONB,                   -- таблицы файла для просмотра (список ReplyTable)
    pages               INTEGER,                 -- страниц PDF
    file_total          NUMERIC(15, 2),          -- «ИТОГО» из файла
    chat_attachment_id  BIGINT REFERENCES chat_attachment (id) ON DELETE SET NULL,   -- откуда взят
    uploaded_by         VARCHAR(100),
    uploaded_at         TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_client_offer_file_attachment ON client_offer_file (chat_attachment_id);
```

- Не рыночная: читается только через КП с гардом рынка (как `client_offer_item`). Отдельная таблица — чтобы журнал и редактор не тянули байты файла.
- Один файл на КП; заменить — удалить КП и занести заново.

## 6. API

- `GET /api/private-requests/{id}/offer-file/candidates` → файлы наших сообщений переписки сделки, новые сверху: `{attachmentId, fileName, sizeBytes, kind, sentAt, channel, subject, text (до 200), looksLikeOffer, usedByOfferId, usedByOfferLabel, aisOfferId, aisOfferLabel}`. Любой вошедший; гард заявки (`PrivateRequestService.findById`, иначе 404).
- `POST /api/private-requests/{id}/offer-file` (ADMIN) — multipart: `file` **или** `attachmentId`; `status` = `SENT` | `ACCEPTED`; `sentOn` (дата, не в будущем). → `ClientOfferResponse` созданного КП. Файл переписки — только наш и только из переписки этой сделки (иначе 404); PDF самой АИС этой сделки — 400 (раздел 4.7).
- `POST /api/private-requests/{id}/offer-hints/{attachmentId}/dismiss` (ADMIN) — «Не КП» / «Нет»; тот же гард файла.
- `POST /api/client-offers/{id}/status` — необязательное `sentAt` (не в будущем): «Отметить отправленным» ставит время письма; без него — как сейчас («сейчас», если не было).
- `GET /api/client-offers/{id}/file` — файл КП (`attachment` с именем по RFC 5987, `nosniff`, `no-store`; тип — только из белого списка, как у файлов ответа поставщика); `GET /api/client-offers/{id}/file/pages/{n}` — страница PDF PNG (n с 1, до 30). Любой вошедший; КП чужого рынка — 404; у КП не из файла — 404.
- У КП из файла `GET /{id}/pdf`, `/docx`, `/preview` — 400 «КП из файла — скачайте файл».
- `ClientOfferResponse` — + `origin`, `file: {name, kind, sizeBytes, parseStatus, parseNote, pages, fileTotal, tables, rowsTotal}` (у КП из файла); журнал — + `origin`.
- `DealProgress.Next` — + `hintId` (файл переписки подсказки); новые действия `ATTACH_OFFER_FILE` (refId — нет, hintId — файл) и `MARK_OFFER_SENT` (refId — КП, hintId — файл).
- `DELETE /api/client-offers/{id}` — у КП из файла в любом статусе (вместе с ним уходят его события в `deal_event` — смена статуса КП с `ref_id` = КП: ссылки на удалённое КП в истории не остаются); у конструктора — как сейчас, только черновик.
- `POST /api/client-offers/{id}/duplicate` у КП из файла → КП конструктора (номер из счётчика, строки с ручными ценами).

## 7. Интерфейс

- `pr-offers` (раздел «КП клиенту» страницы заявки): «Занести готовое КП» рядом с «Создать КП клиенту» (админ, позиции не обязательны); окно — новый компонент `pr-offer-file-dialog` (ленивый чанк): два способа, статус и дата, «Занести» → редактор КП.
- `deal-progress`: подсказка — текст, кнопка действия и вторичная ссылка «Не КП» / «Нет»; страница заявки обрабатывает `ATTACH_OFFER_FILE` (окно с выбранным файлом), `MARK_OFFER_SENT` (статус с `sentAt` → обновить этапы и ленту), отказ.
- Редактор КП (`client-offer-editor`) — режим `origin === 'FILE'`: строка сверки, без блоков «Цены» / «Условия» / «Оформление», вместо предпросмотра — новый компонент просмотра файла (таблицы файла, страницы PDF по одной через `HttpClient` blob, картинка), «Скачать файл» / «Поделиться» отдают исходный файл (`shared/share.ts`), статус — как сейчас. Строки (`client-offer-items`) — вход «из файла»: без «↺ вернуть расчёт».
- Журнал КП (`client-offers`): метка «из файла»; подпись КП без номера — «КП от ДД.ММ.ГГГГ».
- Начальный бандл не растёт: новое — в ленивых чанках (§12, предел ошибки 1,5 МБ).
- Стили — токены UI-kit, тинты по правилам §12, цели 40 px на телефоне, обе темы; классы — не совпадающие с классами kit (§12, «Ответ поставщика — фронт»).

## 8. Крайние случаи и ошибки

- **Файл больше 15 МБ** — 400 «Файл больше 15 МБ — уменьшите его и загрузите снова» (nginx выше 15 МБ — 413, тот же текст на экране). **Не Word, Excel, PDF и не картинка** — 400 «Нужен Word, Excel, PDF или картинка».
- **Разбор не удался** (пароль, повреждён, таблицы нет) — КП всё равно заводится с файлом и статусом; строки — из позиций без цен (как 4.6); строка сверки — причина и «впишите цены по документу».
- **Тот же файл дважды** — разрешено (второе КП: «занесено: КП № 24» в окне предупреждает).
- **Сделка без переписки** — только «С компьютера»; подсказок нет.
- **Файл переписки удалён** (чат удалён) — `chat_attachment_id` обнуляется, КП и его файл живут.
- **Несколько КП в сделке** — «главное» КП по прежнему правилу (принятое → последнее отправленное → последний черновик); новое занесённое «Отправлено» становится главным, если принятого нет.
- **КП из файла и плашка «новые цены»** — как у любого КП: только у черновика.
- **Цена в файле с копейками / большие суммы** — пределы суммы строки и итога те же (`ClientOfferService.checkAmounts`: 400, а не ошибка базы).
- **Рынок РФ** — то же самое, переписки нет; валюта — рубли.
- **Откат кода ниже V33** — прежний бэкенд не знает `origin`: КП из файла он покажет как КП конструктора («Исх. № null», предпросмотр без файла), а PUT КП без номера отклонит. Перед откатом — SQL удаления КП из файла (в DEPLOY.md при раскатке).
