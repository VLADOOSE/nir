# Импорт тендеров: «не терять тендеры» (пакет 1) — дизайн

Дата: 2026-10-07. Источник находок и приёмки — `docs/reviews/2026-10-06-import-review.md` (A1–A5, B3, C1).
Ветка: `feature/import-no-lost-tenders`.

## Цель

Всё профильное (медизделия и медтехника), что есть на goszakup и СК-Фармации, попадает в АИС **целиком**;
то, что не попало или попало не целиком, видно в итоге прогона (ошибка с причиной), а не молча.

Критерии успеха:
- на замороженном корпусе реальных объявлений новые фильтры узнают профильные лоты, которые старые теряли,
  и не начинают пропускать лекарства/услуги/хозтовары (отчёт «было/стало» + golden-тест);
- ни одна площадка не обрезает список лотов молча; неполный список не удаляет лоты;
- разовый сетевой сбой не выкидывает больницу/объявление из прогона;
- дробное/нулевое количество и нулевая сумма не роняют тендер;
- зависшее тело ответа не вешает прогон: он кончается ошибкой с причиной.

Вне рамок: автозапуск и Telegram (пакет 2), цена за единицу goszakup, время дедлайна, B4–B7 (пакет 3),
C2–C5, D1, D3.

## 1. Фильтры релевантности (A1, A2)

**Общий словарь** `integration/MedicalGoodsVocabulary` (только списки/шаблоны терминов, без решений):
- `DEVICE_STRONG` — однозначные виды изделий (анализатор, томограф, эндоскоп/гастроскоп/бронхоскоп,
  микроскоп, центрифуг, маммограф, дефибрил, тест-полоск, экспресс-тест, тест-систем, реагент, пробирк,
  катетер, шприц, перчат, электрод, контейнер для…, насос инфузионн/шприцев, концентратор, кушетк, светильник
  операционн, стол операционн, шовн, имплант, протез …); итоговый список — из golden-корпуса;
- `DEVICE_WEAK` — общие слова, достаточные только без вето (аппарат, система, набор, комплект, установк,
  монитор, материал …);
- `SERVICE_STRONG` — всегда «не товар»: услуг, работы по, ремонт, обслуживан, утилизац, отход, аренд,
  страхован, поверк, метролог, обучен(ие как предмет лота), летательн, беспилотн, дрон, пошив, стирк;
- `SERVICE_WEAK` — «не товар», только если нет термина изделия: осмотр, удаление, замер, монтаж, потолок;
- `MEDICINE` — маркеры лекарств (таблетк, ампул, капсул, мазь, сироп, инъекц, инфузи, сыворотк, аэрозол,
  вакцин, инсулин, «раствор для», мг, мг/мл …).

Все регулярные выражения — `(?iU)` (на JDK 19+ без `U` `\b`/`\w` не работают с кириллицей). Многословные
термины проверяются по словам независимо (стем каждого слова), а не одной подстрокой «стем пробел стем».

**goszakup** (`MedicalRelevanceFilter`, интерфейс `isRelevant(announcementName, lots)` сохраняется, но лот
передаётся как пара «название, описание», а не склеенная строка):
- `SERVICE_STRONG` ищется **только в названии** лота → отсекает всегда;
- `SERVICE_WEAK` ищется только в названии → отсекает, если в названии нет `DEVICE_*`;
- термины изделий ищутся в названии **и** описании;
- описание маркерами услуг не проверяется: описание поставки изделия обычно содержит «монтаж, обучение
  персонала» и раньше убивало лот;
- лекарственное вето у goszakup не вводится (поведение текущего golden-набора не меняем);
- лот, где совпали и изделие, и маркер услуги/лекарства, — INFO-лог (для будущего тюнинга).

**СК-Фармация** (`SkPharmacyRelevanceFilter`):
- лот — изделие, если есть `DEVICE_STRONG`, либо есть `DEVICE_WEAK` и нет `MEDICINE`;
- `MEDICINE` отсекает лот только при отсутствии `DEVICE_STRONG` («Анализатор … в сыворотке», «Насос
  инфузионный» — изделия; «Раствор для инфузий» — нет);
- ступень 1 (`nameCandidate`) прежняя; имя объявления с «медицинской техники» / «медицинских изделий» —
  достаточный признак релевантности тендера (`isRelevant` = true независимо от лотов).

## 2. Полнота лотов (A3, A4)

**Райтер СК-Фармации** получает признак полноты (у goszakup неполный ответ — ошибка до записи, флаг не нужен): `upsert(…, lots, complete)`. При `complete=false` новые и совпавшие
лоты пишутся/обновляются, **несовпавшие существующие не удаляются** (orphanRemoval не срабатывает);
прочее (0 лотов при существующих → ошибка) — как сейчас.

**СК-Фармация** (`SkPharmacyImportService.fetchLots`):
- `max-lot-pages` 20 → 200 (конфиг `skpharmacy.import.max-lot-pages`);
- после обхода — сверка с `SkAnnounce.lotsCount` (если известен): получено < ожидаемого (упор в предел,
  страница без таблицы посреди, обрыв) → запись с `complete=false` + ошибка прогона
  «объявление N: на площадке K лотов, получено M — лишние лоты не удалялись»;
- 0 лотов при `lotsCount > 0` (и не услуги) → ошибка «лоты не разобраны», тендер не создаётся/не трогается;
- обход страниц прекращается на странице без новых кодов или без «следующей», как сейчас.

**goszakup** (`GoszakupHttpClient.fetchLots`):
- запрос с максимальным `limit`, который принимает API (уточнить живьём токеном; иначе 50), и переход по
  `next_page` до конца, с пределом страниц;
- сверка с `total`: собрано меньше → `IncompleteLotsException` → объявление в ошибки прогона, лоты не
  трогаются (у goszakup неполный ответ — сбой, а не норма).

## 3. Повторы сетевых сбоев (A5)

- Общий `integration/http/UpstreamRetry.withRetries(call)`: 3 попытки, паузы 1 с и 3 с; повторяются только
  исключения с признаком «повторяемо» (обрыв, таймаут, 5xx, 429); 4xx и ошибки разбора — сразу наружу.
  `GoszakupRetry` заменяется им (ТЗ и скачивание — как раньше, 3 попытки).
- Признак «повторяемо» несёт исключение клиента (`UpstreamCallException(retryable)` или поле в существующих
  исключениях — решается в плане, тексты ошибок прежние, без адресов/токена).
- Повтор — на: страницу ленты больницы goszakup, `subject`, лоты goszakup, страницы ленты/лотов/общих
  сведений СК-Фармации. Паузы — внедряемый `Sleeper` (в тестах без сна).
- `fetchSubject` — **после** фильтра релевантности и с кешем по БИН на прогон. Сбой `subject` (после
  повторов) тендер не роняет: тендер пишется без subject, и в этом случае `customerName`, `regionKato`,
  `deliveryAddress` существующего тендера **не затираются** пустыми; регион — из реестра больниц, как сейчас.

## 4. Количество и сумма (B3)

- Количество: целое > 0 → как есть; дробное, 0, отрицательное, нераспознанное → `null`.
  У СК-Фармации парсер перестаёт отрезать дробную часть («2.5» → null, а не 2; «1.00» → 1).
  У goszakup `LotDto.count` — `BigDecimal`.
- Когда количество отброшено, в начало описания лота добавляется строка «Количество на площадке: 2,5» —
  только если описание пишется с площадки в этом проходе (goszakup — пока ТЗ не разобрано; СК-Фармация —
  когда поле пустое) и строки ещё нет.
- Сумма лота goszakup `amount` ≤ 0 или переполнение NUMERIC(15,2) → `null` (как уже у СК-Фармации).

## 5. Дедлайн на весь HTTP-обмен (C1)

- `LimitedBytes` и `FileTooLargeException` переезжают из `integration/whatsapp` в `integration/http`
  (у WhatsApp меняются только импорты). `GatewayHttp` остаётся в WhatsApp: его тексты намеренно без причины
  (у Green-API токен в URL), а импорту причина нужна («PKIX path building failed») — поэтому рядом свой
  `integration/http/UpstreamHttp` (уточнено при планировании, 2026-10-07).
- `GoszakupHttpClient`, `SkPharmacyHttpClient`, `SkTechSpecHttpClient` — через `UpstreamHttp.exchange` с
  `LimitedBytes`: дедлайн 60 с (JSON/HTML), 120 с (PDF); предел тела 10 МБ (JSON/HTML), 30 МБ (PDF);
  `HttpClient.Version.HTTP_1_1`.
- Редиректы: СК-Фармация — `Redirect.NORMAL`; goszakup — без редиректов (токен в заголовке не должен уйти
  на чужой хост; C5 не ухудшаем).
- Превышение дедлайна/предела — ошибка с причиной («… не ответил за 60 с при …», «… больше 10 МБ»),
  классифицируется как повторяемая (дедлайн) / неповторяемая (предел).

## 6. Замер «до/после» — замороженный корпус

Первая задача плана снимает корпус живьём (токен goszakup — `~/.config/ais/goszakup.token`, не печатать)
и кладёт в `src/test/resources/import-corpus/`:
- goszakup: объявления 29 больниц ЗКО за 30 дней — номер, имя объявления, лоты (название, описание);
- СК-Фармация: первые 5 страниц ленты — номер, имя, лоты (название, описание).

Только тексты закупок (публичные данные площадок), без контактов. Разметка «профильный / нет» — вручную
для расхождений старого и нового фильтра и для выборки из остального (лекарства, услуги, хозтовары).
Тест-отчёт печатает «было/стало» по тендерам и лотам; golden-тест закрепляет разметку.
Живой прогон ЗКО и СК-Фармации локально — приёмка в конце (цифры в PROGRESS).

## Обработка ошибок и видимость

Всё новое — через `ImportSummary.addError` («где: что»), значит видно в тосте (синий/красный) и в строке
«Обновлено…». Нового UI не требуется.

## Тестирование

- На каждый пункт — тест, красный до правки (фикстуры: двухстраничный ответ лотов goszakup
  `{total, limit, next_page, items}`; страницы СК-Фармации с упором в предел и с пустой страницей посреди;
  стаб «заголовки пришли, тело встало»; клиент, падающий первым вызовом).
- Мутации: «неполный список — не удаляем», «4xx не повторяем», «маркер услуги в описании не отсекает
  изделие», «лекарственное вето при сильном изделии», «subject null не затирает заказчика».
- Гейт: `./gradlew cleanTest test` — 0 падений; фронт не меняется.
